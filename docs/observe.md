# Observation checklist

Generated by `cargo xtask observe` from `spec/inventory/*.toml`; do not edit. `cargo xtask ci` fails when it is out of date.

Clean-room: observe the reference app on our own synthetic fonts; never copy its assets or text.

## What is listed

Every inventory row that watching the running reference app could settle:

- rows with `guesses`: choices of ours where no source says what the reference does;
- rows whose `status` is `memory` (recalled), and rows whose `status` is `inferred` (our design) that point at a handbook chapter;
- rows with `observe` steps: one concrete thing to do in the app and what to look for.

Left out: rows already `observed`, rows with `own = true` (no counterpart in the reference app), and rows that other tools settle (command-line rows, quality checks, binary tables).

Rows of built milestones come first, because their guesses are behaviour FontCraft already has. Within a milestone group the rows are sorted by the place in the app where the check happens, so one sitting can stay in one window. `live` after a row's status marks a command FontCraft registers today, which can be tried side by side.

## How to record a result

Edit the row in `spec/inventory/*.toml`:

1. Write what the app did and the date in the row's `notes`.
2. Remove each guess the observation settles. If the app does something else, change FontCraft's behaviour and the row's `summary` to match.
3. Remove the `observe` steps you carried out.
4. When nothing about the row is left open, set `status = "observed"`.
5. Run `cargo xtask guesses` and `cargo xtask observe` and commit the regenerated files.

The checkboxes are for a printed or copied list; a settled row drops out of this file when it is regenerated.

To add a check, append a step to the row's `observe` list: what to do, and what to look for.

### Kerning and the Kerning window (3)
