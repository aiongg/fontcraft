# 21 · Font audit (quality checks)

Inventory: `spec/inventory/21-qa-checks.toml` (287 `[[check]]` rows, 31 `[[command]]` rows, the panel rows and the
`audit.*` behaviour rows). Sources: FontBakery check definitions and profiles, AFDKO `checkoutlinesufo` and
`comparefamily`, AFDKO `docs/MSFontValidatorIssues.md`, fontTools `varLib.interpolatable` and `ttLib.removeOverlaps`.
45 rows are our own design (`status = "inferred"`, marked `*` in the tables below): the outline and source
checks an editor's audit panel is expected to offer.

## 1. Model

One registry of checks serves every surface. `fontcraft-cli check`, the Font Audit panel, the control channel and
the MCP server all call the same commands (`audit.run`, `audit.list`, `audit.fix`, …); none of them contains check
logic.

A check is a pure function from a target to a list of results. Each check has:

| Property | Meaning |
|---|---|
| `id` | `check.<group>.<camelCaseName>`; stable, used in profiles, ignore lists and reports |
| group | `outlines`, `components`, `anchors`, `glyphset`, `metrics`, `names`, `tables`, `layout`, `variations`, `hinting`, `kerning`, `family`, `files`, `sources`, `color`, `cid`, `vendor` |
| severity | `fail`, `warn` or `info`: the most severe result the check emits by default |
| scope | `source` (reads the editable document), `binary` (reads compiled tables), `family` (compares two or more fonts) |
| home profile | the smallest built-in profile that contains it (§2) |
| preconditions | facts that must hold for the check to run (TrueType or CFF outlines, variable, hinted, table present, script covered, project value set, network allowed); otherwise the check is recorded as skipped with the reason (`audit.preconditions`) |
| message codes | short kebab-case codes for the distinct things one check can report; each code has its own default severity (`audit.severityOverrides`) |
| thresholds | named numeric or list parameters with defaults (for example `tolerance`, `minArea`, `kinkiness`, `maxResults`), settable per run, per document and per profile |
| fix | the id of an automatic repair, when one is well defined (§5) |

Scope resolution (`audit.scopeResolution`): when the target is a source, `binary` checks run on an in-memory compile of
each exporting instance (and of the variable font, when the source defines one) and their findings are mapped back to
source glyphs, masters and Font Info fields where a mapping exists. When the target is a font file, `source` checks
that only need outlines, components, anchors, metrics or kerning run on the decoded file; checks that need source-only
data (smooth flags, metrics keys, alignment zones of a master, backup layers) are skipped. `family` checks need at
least two fonts: a directory, a list of files, the instances of one source, or the fonts open in the editor.

Milestones: the `source`-scope rows of the `outlines` group, together with `audit.run`, `audit.list`,
`audit.describe`, `audit.results`, `audit.fix`, `audit.profile.list`, live audit and canvas markers, are M3, because
Edit View needs them while drawing. Everything else is M12.

## 2. Profiles

Four built-in profiles, defined by each check's home profile:

| Profile | Contains | Checks | Intended use |
|---|---|---|---|
| `outlines` | checks whose home is `outlines` | 46 | Per-glyph geometry, components, anchors and master compatibility on a source. Fast enough to run on every edit (live audit) and before every export. |
| `opentype` | checks whose home is `opentype` | 47 | Conformance of a compiled font with the OpenType specification: the counterpart of FontBakery's `opentype` profile plus the spec-level facts `comparefamily` tests. A failure here is a compiler or Font Info error. |
| `universal` | `outlines` + `opentype` + checks whose home is `universal` | 188 | The default. Adds practices that hold for any professional font regardless of distributor: the counterpart of FontBakery's `universal` profile, the widely applicable `comparefamily` tests, and source-consistency checks. |
| `strict` | everything | 288 | Adds house-style, legacy and heuristic checks: Adobe Type conventions from `comparefamily`, checks taken from vendor profiles (Google Fonts, Adobe Fonts, Microsoft, Type Network, Noto, Fontwerk, Font Bureau), informational reports, and the opt-in ones (network, external validator, shaping test suites). |

`outlines` and `opentype` are disjoint; `universal` is a superset of both; `strict` is a superset of `universal`.

Rules used to assign a home profile:

- `outlines`: reads one glyph (all its masters) of a source and needs no compile. Includes the ten
  `varLib.interpolatable` problem types except `overweight`.
- `opentype`: the check states a requirement of the specification, or a consistency between two tables that the
  specification implies.
- `universal`: a recommendation that does not depend on who ships the font. Every check of FontBakery's `universal`
  profile lands here or lower, except the ones noted in §9.
- `strict`: correct only under a house convention (Macintosh name records kept, embedding value 8, typo metrics
  summing to the em), or a heuristic with many false positives, or needs data we must author ourselves (shaping
  expectations, reference glyph sets), or is informational.

Some pairs of checks encode opposite policies and are never both active: `names.noMacRecords` (universal) against
`names.macRecordsComplete` and `family.macWindowsMenuNames` (strict, off unless the project sets
`keepMacNames = true`); `metrics.lineGaps` (zero line gap) against `metrics.typoMetricsVsEm` (Adobe scheme);
`metrics.verticalMetricsScheme` selects one scheme by parameter.

User and project profiles (`audit.profile.save`) are built the way FontBakery profiles are: a list of included
profiles, checks added, checks excluded, severity overrides per check or per message code, and threshold defaults.
User profiles live in application settings; project profiles live beside the source so that a repository carries
its own rules. A document stores the id of its default profile (`audit.profile.setDefault`), its threshold
overrides (`audit.config.set`), its project values (`vendorId`, `defaultUrl`, `fsType`, `allowedTables`,
`glyphSet`, `keepMacNames`, `warnSize`, `failSize`) and its ignore list (`audit.ignoreIssue`).

The vendor profiles of FontBakery are not shipped as built-in profiles. Their generally applicable checks are
individual `strict` rows; the rest is summarised in the `vendor` group (§8) as candidates for plug-in profiles.

## 3. Running an audit

`audit.run` takes a target (default: the current document), a profile (default: the document's default profile,
else `universal`), optional check and group filters with glob patterns (`check.outlines.*`), optional glyph and
master filters, threshold overrides, and `minSeverity`. It returns the result document of §4 and changes nothing.

- Cache (`audit.glyphHashCache`): per-glyph results of a source are stored with a hash of the glyph; unchanged
  glyphs are not re-examined unless `all` is set. `audit.clearCache` drops the hashes. Font-level and family
  checks always re-run.
- Result cap (`audit.resultCap`): a heuristic outline check that yields more than `maxResults` (default 100)
  results in one font is collapsed into one informational summary result. FontBakery drops such reports entirely;
  we keep the count.
- Order: results are sorted by severity (fail, warn, info), then group, check id, glyph order, master.
  `audit.checkInterpolation` instead keeps the problem-type order of the reference: missing glyph, open path,
  path count, node count, node type, contour order, start point, kink, underweight, overweight.
- Network: checks that need it never run unless the call sets `network: true` (`audit.networkOptIn`).

Command line. The `[[cli]]` row for `fontcraft-cli check` belongs to the command-line inventory; this is the
mapping it must implement:

| `fontcraft-cli check` argument | `audit.run` / other command |
|---|---|
| `FONT_OR_SOURCE...` (several files or a directory make a family) | `target` |
| `--profile ID` | `profile` |
| `--check ID_OR_GLOB`, `--exclude ID_OR_GLOB`, `--group NAME` | `checks`, `exclude`, `groups` |
| `--glyphs LIST`, `--glyph-file PATH`, `--master ID` | `glyphs`, `masters` (list syntax: `audit.glyphSelectionSyntax`) |
| `--set CHECK.NAME=VALUE` | `config` |
| `--min-severity`, `--fail-on info\|warn\|fail` | `minSeverity`; exit status (`audit.exitStatus`: 0 clean, 1 findings at or above `--fail-on`, 2 usage error, 3 unreadable target) |
| `--all` | `all` (ignore the cache) |
| `--fix`, `--fix-unsafe`, `--dry-run`, `-o OUT` | `audit.fix` after the run, with `safeOnly`, `dryRun`, `output` |
| `--format json\|text\|markdown\|html`, `--report PATH` | `audit.export` |
| `--list`, `--describe ID`, `--profiles` | `audit.list`, `audit.describe`, `audit.profile.list` |
| `--quiet` | print nothing, exit status only |

Three shortcut commands reproduce the reference tools with their own option sets (§6): `audit.checkOutlines`,
`audit.checkInterpolation`, `audit.compareFamily`, plus the four `audit.report.*` table reports.

Relation to commands in other inventories:

- `interpolation.checkCompatibility` (interpolation inventory) is the editor's quick compatibility query: the
  first mismatch per layer pair. The structural `check.variations.*` checks (missing glyph, path count, node
  count, node type, component and anchor mismatch) must use the same engine routine so the two never disagree;
  the audit adds the heuristic tests (contour order, start point, kink, weight) and reports every mismatch.
- `window.compareFamily` and `window.compareFonts` (interpolation inventory) are the primary reference's
  side-by-side attribute tables for open documents. `audit.compareFamily` is a different thing: the pass/fail
  family checks of AFDKO comparefamily on compiled fonts. The shared name is a hazard; see open question 13.

## 4. Result format

One JSON document per run. `audit.results` returns the same shape from the cache; `audit.export` writes it or
renders it as text, Markdown or HTML.

```json
{
  "schema": "fontcraft.audit/1",
  "tool": {"name": "fontcraft", "version": "0.12.0"},
  "target": {
    "kind": "source",
    "path": "Example.fontcraft",
    "fonts": [{"id": "f0", "name": "Example-Bold", "path": null, "instance": "Bold", "format": "ttf"}]
  },
  "profile": "universal",
  "config": {"check.outlines.tinyContour": {"minArea": 25}},
  "summary": {"fail": 1, "warn": 1, "info": 0, "passed": 148, "skipped": 37, "ignored": 0, "errors": 0},
  "checks": [
    {"id": "check.outlines.overlap", "status": "warn", "results": 1, "durationMs": 12},
    {"id": "check.hinting.smartDropout", "status": "skipped", "reason": "font has no TrueType instructions"}
  ],
  "results": [
    {
      "id": "r17",
      "check": "check.outlines.overlap",
      "code": "overlap",
      "severity": "warn",
      "message": "Contours 1 and 3 overlap.",
      "location": {
        "font": "f0", "glyph": "ampersand", "master": "m02", "layer": "m02",
        "contours": [0, 2], "nodes": [], "point": [312, 148], "bounds": [280, 120, 344, 190]
      },
      "data": {"contourCountBefore": 3, "contourCountAfter": 2},
      "fix": {"available": true, "id": "removeOverlap", "safe": true,
              "command": "audit.fix", "params": {"results": ["r17"]}},
      "ignored": false,
      "stale": false
    },
    {
      "id": "r18",
      "check": "check.metrics.winAscentDescent",
      "code": "ascent",
      "severity": "fail",
      "message": "OS/2.usWinAscent is 900 but the tallest glyph reaches 1042.",
      "location": {"font": "f0", "table": "OS/2", "field": "usWinAscent", "glyph": "Aringacute",
                   "sourceField": "master.customParameters.winAscent"},
      "data": {"actual": 900, "expected": 1042},
      "fix": {"available": true, "id": "syncVerticalMetrics", "safe": false,
              "command": "audit.fix", "params": {"results": ["r18"]}},
      "ignored": false,
      "stale": false
    }
  ]
}
```

Field rules:

- `checks[].status`: `pass`, `fail`, `warn`, `info` (the worst result of that check), `skipped` (precondition not
  met; `reason` given) or `error` (the check itself failed; `message` given, counted in `summary.errors`, and
  treated as a failure for the exit status).
- `results[].severity`: `fail`, `warn` or `info`, after profile overrides. `code` identifies which of the check's
  messages this is.
- `results[].message` is for people: it counts nodes, handles and paths from 1. `location` and `data` count
  from 0, as every command address does.
- `results[].location` holds only the keys that apply. Glyph-level: `glyph`, `master`, `layer`, `contours`,
  `nodes` (as `[contour, node]` pairs), `components`, `anchors`, `point`, `bounds`. Table-level: `table`, `field`,
  `nameId` with `platform`/`language`, `feature`, `script`, `language`, `lookup`, `axis`, `instance`, `pair`
  (kerning, two glyph names). Family-level: `fonts` (ids of every font involved). Interpolation: `masters` (the two
  compared), and for a contour-order result `order`, the proposed shape order of the layer (every shape index
  once, as `glyph.setShapeOrder` takes it); a start-point result names the proposed start node in `nodes`. `sourceField` names the Font Info
  field or custom parameter that produces a compiled value, when known.
- `results[].data`: machine-readable values behind the message (actual and expected values, scores, lists of
  codepoints). Messages are for people; agents should read `data`.
- `results[].fix`: `available` is false when the check has no fix or this particular result cannot be repaired
  automatically (for example an open path whose ends are far apart when `safeOnly` applies). `safe` is true when
  the fix does not change the rendered shape, metrics or naming seen by users.
- `id` values are stable within one cached run and are what `audit.fix`, `audit.revealIssue` and
  `audit.ignoreIssue` accept. `stale` is set by `audit.results` when the glyph changed after the run.
- On a source, glyph-level locations use the addresses of the editing commands (decision 0004):
  `shapes` (indices in the layer's shape list), `points` (`[shape, node]`, off-curve nodes
  included) and `segments` (the `[shape, node]` of the node that ends the segment). These can be
  passed straight to a path command as its targets.
- Text output prints one line per result: `SEVERITY check-id [font] glyph/master: message`, followed by a summary
  line. Markdown and HTML group by check and include the check's description.

## 5. Fixes

A fix is a named repair attached to a check (`fixable = true`). `audit.fix` selects results (by result id, or by
check and glyph filters), groups them by fix id and glyph, applies each fix once per glyph and master, re-runs the
affected checks, and returns `{applied: [...], skipped: [...], remaining: <result document>}`. Rules:

- One call is one undo step (`audit.fixIsOneUndoStep`). Each fix is carried out by an ordinary engine command, so
  it appears in the command log and can be replayed by an agent without the auditor.
- `safeOnly` defaults to true: only fixes flagged safe run. Fixes that alter design decisions (vertical metrics,
  style linking, snapping points to metric lines, deleting glyphs or kerning) need `safeOnly: false`.
- `dryRun` returns the planned edits (`{fix, glyph, master, description}`) without touching the document.
- Source glyph fixes keep the untouched outline in a backup layer of the same master unless
  `keepOriginal: "none"` (`audit.fixKeepsOriginal`).
- Outline fixes follow a fixed order, round afterwards and try to keep contour order and start points
  (`audit.outlineFixOrder`, `audit.outlineFixRounding`, `audit.outlineFixKeepsContourOrder`).
- Binary targets: only the table-level fixes apply (`patchTable`, `dropTables`, `cleanNameRecords`,
  `cleanInstances`, `rebuildCmap`, `recompileCff`, …) plus overlap removal on `glyf`/`CFF` outlines. Overlap
  removal in a compiled font by default drops the hinting of every glyph (optionally only of the glyphs it
  changed) and removes CFF subroutines that became unused, as `ttLib.removeOverlaps` does; glyphs on which the operation errors are left unchanged and
  reported.
- Source targets: a result that comes from a compiled value (`scope = "binary"`) is fixed in the source, by
  changing the Font Info field or custom parameter named in `location.sourceField`, never by patching the
  compiled copy. Where the value is one the compiler derives (bounding boxes, averages, checksums), there is
  nothing to fix in the source and the result is a FontCraft compiler bug.

### Fixes in M3

`audit.fix` repairs the open document. What it does:

| Step | Rule |
|---|---|
| Selection | Result ids of the kept run (`results`), or the filters of `audit.run`. A result whose glyph changed since the run is skipped. With filters, only findings that have a fix are selected; the result cap does not hide any |
| Per layer | A locked glyph is skipped. With `safeOnly`, a layer with components is skipped, and so is a fix that is not safe |
| Order | Close open paths, Tidy up Paths, Remove Overlap, Tidy up Paths again (only after an overlap removal), Correct Path Direction, Add Extremes, add inflections, start points, Round Coordinates |
| Each step | The layer is checked again, and the step's command runs on the paths the check reports now, so later steps get current addresses. A step whose check reports nothing is left out |
| Start points | `path.makeNodeFirst` on the lowest, then leftmost, node, only when every master's path at that index has its lowest node at the same index |
| Backup | Before the first change, `layers.addBackupLayer` copies the layer to a backup of its master, unless `keepOriginal: "none"`. A layer the fix leaves as it was gets no backup |
| Failure | A command that fails leaves the layer and its backup as they were, and the layer is listed in `skipped` |
| Undo | The whole call is one undo step; the result lists each command call with its parameters |
| Report-only | A fix whose command is not built yet is listed in `skipped` |

`audit.run` keeps the last run of each open document until the next run or until the document closes;
saving keeps it;
`audit.results` returns it and marks results whose glyph changed since as `stale`. Runs examine
every layer of the selected glyphs except backup layers, unless `layers` names them.

### Fix calls

M12 takes `audit.fix` from layer checks to every scope. The M3 rules above still hold for each layer.
M12 adds these rules:

| Rule | What happens |
|---|---|
| Results from compiled fonts | On a source target, a result of a `binary` or `family` check that names a glyph is fixed on the source glyph the compiled glyph came from, found through the compile's map from production names to glyph names. A result with no source glyph, and a result about a value the compiler derives, is listed in `skipped` with the reason |
| Masters | A result that names a layer is fixed on that layer. A glyph result from a compiled font is fixed on every master layer of the source glyph |
| Stages | Three stages: font-wide fixes of glyph data (steps 1 to 6 below), then the layer steps for each layer (7 to 33), then font-wide fixes that read the final outlines (34 to 38). Each step checks again before it runs and builds its calls from what the check reports now. A font-wide step whose call fails is undone as a whole and listed in `skipped`. A feature-code step that cannot fix the result through the stored code (an automatic entry, lookups defined outside the features) is skipped with the reason |
| Layers with components | The M3 rule that `safeOnly` skips a layer with components applies to the outline steps (12 to 29) only; the component steps (8 to 11) exist to change such layers |
| Font Info fixes | `syncVerticalMetrics`, `syncVersion`, `syncStyleLinking`, `syncFamilyValues`, `sortZones`, `clearInfoFields` and the source side of `cleanNameRecords` and `cleanInstances` run in the first stage, once per call, through the commands § 5 names (their rows give the parameters) |
| File targets | The table repairs run in the order of the last table below, each call reading the previous call's output. The calls write to a temporary file next to the output, which replaces the output (or the input with `inPlace`) only when every call succeeded. Fixes that edit glyph data in a source are skipped on file targets with that reason |

Source targets. "As in M3" means the call of the M3 table above. Location keys are those of § 4.

## 6. Behaviour carried over from the reference tools

### checkoutlinesufo → `audit.checkOutlines`

Tests, in the order the tool runs them: coincident points, flat curves, collinear lines (all three before overlap
removal so that the before/after comparison is fair), overlap (union repeated until the point digest stops
changing), tiny contours (a by-product of overlap removal), collinear lines again; glyphs with no contours are
reported unless they are named as spaces. Components are decomposed before testing.

| Option | Meaning | FontCraft |
|---|---|---|
| `-e`, `--error-correction-mode` | repair what is reported | `fix: true` → `audit.fix` |
| `--no-overlap-checks` | skip overlap and tiny-contour tests | `overlapChecks: false` |
| `--no-basic-checks` | skip coincident points, flat curves, collinear lines | `basicChecks: false` |

The document lists messages of an external validator that are wrong or irrelevant for well-built fonts. We use it
two ways. First, as a filter list when `files.externalValidator` imports that validator's output. Second, as a
guard on our own checks, so that we do not repeat the mistakes:

| Message family | Our rule |
|---|---|
| gasp, kern, hdmx, VDMX "recommended table missing"; rasteriser needs `glyf` | `tables.recommendedTrueTypeTables` and `hinting.gasp` never fire for CFF fonts |
| Non-null feature parameters for `size`; `ss01`… reported as unregistered | `layout.validFeatureTags` knows every registered tag including `ssNN` and `cvNN`; feature parameters are legal |

| `lowestRecPPEM` unreasonably small | `tables.lowestRecPpem` is informational |

## 7. Font Audit panel and Edit View

Panel `window.fontAudit` (inventory row lists the controls). Behaviour:

- Running: the Run button runs the chosen profile on the chosen target in steps (`audit.start`, then one
  `audit.step` a frame, through `audit.panel.continue`). A progress bar counts the layers examined and the three
  later stages (glyph and source checks, compiling, binary and family checks). Cancel (`audit.cancel`) stops the
  run: the font and the kept run do not change, and the panel lists what the run had found, marked partial, with
  Fix and Ignore off. A family of files runs in one `audit.run` call.
- Run ids: every result document has a `runId`. `audit.results`, `audit.fix`, `audit.export` and
  `audit.revealIssue` take one and refuse it when the kept (or listed) run is another, so result ids of an old run
  never reach a newer one.
- Listing: results are grouped by check (default), glyph or severity (`audit.filterResults`). A check row shows its
  description and result count; a result row shows severity, glyph or table, master and message. Ignored results
  are hidden unless "show ignored" is on.
- Revealing: Return or double-click calls `audit.revealIssue`: glyph results open the glyph in Edit View on the
  right master with the nodes, contours, components or anchors selected and in view; table results open Font Info
  at `sourceField`; family results select the fonts involved.
- Fixing: Fix applies to the selected rows, Fix All Safe to every listed result with a safe fix. Rows disappear or
  change when the re-run finishes. Preview Fix (`audit.panel.previewFix`) lists the edits a dry run of `audit.fix`
  plans for the selected rows; Apply makes them.
- Export Report (gear menu) writes the listed run with `audit.export` as HTML, Markdown, JSON or text
  (`audit.panel.exportReport`).
- Live audit (`audit.liveAudit`, `audit.toggleLiveAudit`): the `outlines` profile re-runs on the glyph being
  edited shortly after each edit. Other profiles only run on request. FontCraft runs it once per document revision
  on the edited layer, never while a drag or a dialog preview is under way. It is off when the app starts.
- Canvas markers (`audit.canvasMarkers`, `audit.toggleMarkers`): results with a geometric location draw a marker
  in Edit View; `audit.nextIssue` and `audit.previousIssue` step through them. Each result has a badge in its
  severity colour beside the spot it names; hovering the badge shows the message, clicking it selects the reported
  nodes, segments and components. Reported nodes get a ring, reported segments and paths are drawn over the
  outline.
- Profiles and thresholds are edited in `dialog.auditProfile`.

### Variations and master compatibility (`check.variations.*`, 38)

Limits on the compatibility tests (`crates/audit/src/checks/compat.rs`):

- A source with more than 256 masters is skipped, with the reason in the report.
- The heuristic tests (contour order, start point, kink, under- and overweight) estimate their
  work on each glyph before they start. A glyph over 250,000,000 steps is skipped, with the
  reason. The work grows with the cube of the contour count for every pair of layers compared,
  so a glyph with 100 contours in 64 masters is over the limit and is skipped.
- Contours with more than 2,000 points are left out of the start-point and weight tests. The
  contour-order test matches at most 256 contours and components.

Notes on the `universal` mapping:

- `fontbakery_version` becomes `files.auditorVersion`, `fontdata_namecheck` becomes `names.nameCollision`; both
  need the network and are `strict`.
- `family/single_directory` is a failure upstream and keeps that severity; it only applies to file targets.
- `ots`, `ttx_roundtrip` and `freetype_rasterizer` wrap external programs upstream. Ours are `files.sanitiser`,
  `files.roundTrip` and `files.rasterises`, implemented with our own parser, dump format and rasteriser.
- `ufolint` wraps an external linter; `sources.ufoStructure` is our own structural validation and applies to UFO
  input only. The native format and `.glyphs` files get the same guarantees from their loaders.
- `superfamily/list` is a listing, not a test; it is folded into `family.superfamilyVerticalMetrics`.
- `varfont/unsupported_axes` keeps its upstream severity but is `strict` only: it reflects browser support at one
  point in time.
- `fontbakery_version` is the one deliberate severity change: a failure upstream, informational here.
- `contour_count` needs a table of expected contour counts per character; ours must be authored independently.
- Two checks exist upstream but belong to no profile (`ufo_consistent_curve_type`, `ufo_no_open_corners`); they are
  `outlines.mixedCurveTypes` and `outlines.openCorners`. `unwanted_tables` (also orphaned) is merged with
  `vtt_volt_data` into `tables.unwantedTables`.

### Vendor profiles

Generally applicable vendor checks have their own rows (search the inventory's `ref` for `googlefonts/`,
`adobefonts/`, `microsoft/`, `typenetwork/`, `notofonts/`, `fontwerk/`, `fontbureau/`). The remainder is
summarised by the eleven `check.vendor.*` rows and is not planned as built-in behaviour:

| Vendor group | Upstream checks | Why not built in |
|---|---|---|
| Google Fonts catalogue metadata | 47 `googlefonts/metadata/*` | test a distributor's sidecar file (METADATA.pb) |
| Google Fonts description and article | 9 `googlefonts/description/*`, `googlefonts/article/images` | test HTML files of the catalogue |
| Google Fonts repository layout | 6 `googlefonts/repo/*` | test a repository convention |
| Google Fonts licensing | 7 checks | tied to OFL text and catalogue policy |
| Google Fonts naming policy | 3 checks | catalogue naming scheme and UPM short list |
| Google Fonts axis registry | 3 checks | need the registry data |
| Google Fonts regressions | 6 checks | compare with the published version; job of the compare tools |
| Noto identity | 4 checks | fixed strings of one project |
| Microsoft delivery | 4 checks | fixed strings; WGL4/OGL2 expressible through `glyphset.minimumCoverage` |
| Fontwerk identity | 1 check | expressible through `tables.vendorId` |
| ISO 15008 legibility | 5 checks | candidate for an optional legibility profile |

Severity changes that vendor profiles apply to shared checks (for example Adobe lowering name and metrics failures
to warnings, Google raising line-gap and italic-angle warnings to failures, Type Network raising sanitiser
warnings) are the model for profile overrides; none of them is baked into the built-in profiles.

## 10. Open questions

1. Menu placement and shortcuts of the audit commands. The primary reference has no audit panel, so every
   `menu = []` and `shortcut = ""` in the inventory is a decision still to make, not an omission.
   **Answered (M12 plan, our decision, 2026-10-11):** Font Audit opens from the Window menu; no audit command has a shortcut; Next and Previous Issue live on the panel and the marker badges. Each is a guess on its row.
2. Fixes without a command. The fixes marked "auditor" in §5 (add inflection nodes, round coordinates, harmonise,
   convert curve type, erase open corners, fix master compatibility, the Font Info and table repairs, …) have no
   command in any inventory. Each needs either a new engine command in the inventory that owns the area or to be a
   parameterised private operation behind `audit.fix`; "everything is a command" argues for the former. The
   table-level fixes depend on the command-line suite's table editor, whose inventory was not available.
   **Answered for M3 (our decision, 2026-10-09):** `addInflections` becomes the command
   `path.addInflections`; Remove Overlap, Tidy up Paths, Correct Path Direction, Add Extremes and
   Round Coordinates are commands already. A fix without a command stays report-only until a command
   exists.
   **Answered for M12 (M12 spec pass):** every fix of §5 has a command. Nine are new `own = true` rows
   in `21-qa-checks.toml` (`path.eraseOpenCorners`, `component.flatten` and the seven `tables.*`
   repairs), `fixCompatibility` reorders shapes with `glyph.setShapeOrder` (M9), the Font Info fixes are M12.63's `font.info.*` and `font.instance.*`
   commands, and the rest use commands of other chapters (feature code, kerning, glyph info, the
   `variations` and `outlines` file commands). §5 › Fix calls says how each call is built.
3. Where a fixed outline goes. checkoutlinesufo writes the fixed glyph to a separate processed layer and leaves
   the default layer alone unless `-w` is given; we propose the opposite (fix in place, original to a backup
   layer) because that is what an editor user expects. To be confirmed against how the build reads layers.
   **Answered for M3 (our decision, 2026-10-09):** in place, with the unfixed layer copied to a
   backup layer first, as `audit.fixKeepsOriginal` proposes (open decision D12).
4. Whether an outline fix on a composite glyph should decompose it. The tool decomposes before testing and writes
   the decomposed result; in an editor, silently decomposing `Aacute` because its parts overlap is rarely wanted.
   Proposal: report, and fix only when asked with `safeOnly: false`.
   **Answered for M3 (our decision, 2026-10-09):** report; fix a composite glyph only with
   `safeOnly: false`.
5. Default thresholds of the inferred checks (`missingExtremes.minDistance`, `almostStraightCurve.maxDeviation`,
   `kinkedSmoothNode.maxAngle`, `unbalancedHandles.maxRatio`, `nearAlignmentZone.margin`, …) are first guesses and
   need tuning on real fonts.
   **A measure of M12** (`docs/plans/M12.md` § 5, threshold survey): results per check counted over the corpus sources; a check that fires on more than 20% of a clean source's glyphs is reviewed.
6. Path-direction convention in sources. The inventory assumes PostScript direction in the source with reversal
   at TrueType export; it must match what the drawing and compile specs decide.
   **Answered for M3 (our decision, 2026-10-09):** sources keep PostScript direction, outer contours
   counter-clockwise (03a question 16); TrueType export reverses contours.
7. Data sets we have to author ourselves because the upstream ones cannot be copied as text: expected contour
   counts per character, the case-mapping exception list, the registered script, language, feature and baseline
   tag lists (from the OpenType registry), code-page and Unicode-range heuristics, working-to-production glyph
   names (from the glyph database), reference glyph sets, shaping expectations per language.
   **Answered (M12 plan):** registered tags typed from the OpenType registry pages; Unicode ranges and code pages ported from fontTools (MIT); expected contour counts and case-mapping exceptions ported from FontBakery's data files (Apache-2.0), each credited; production names from `glyphdata`; reference glyph sets and shaping expectations are project values. Package M12.45.
8. `metrics.monospaceFlags` uses an 80% same-width rule over ASCII upstream; `comparefamily` uses 80% over all
   glyphs for its hint that a font might be monospaced. One rule has to be chosen.
   **Answered (M12 plan, our decision):** the 80% rule over ASCII glyphs; comparefamily's all-glyph hint is not reported separately (guess on the row).
9. Several upstream checks compare the style against the file name (`Family-BoldItalic.ttf`). On a source there is
   no file name; we take the style from the instance's style-linking settings. Binary targets without source may
   need the file-name fallback.
   **Answered (M12 plan, our decision):** on a compiled font without its source the style comes from name IDs 2 and 17 and fsSelection; only `files.canonicalFileName` reads the file name (guess on `audit.familyGrouping`).
10. An illustrated interpolation report (the reference renders each problem as before/after drawings in PDF or
    HTML) would need the proofing renderer; not in this inventory.
   **Open, blocks nothing:** not in M12; `proof` could draw it later.
11. `comparefamily` single-face test 29 is an empty placeholder in the reference; nothing to port.
   **Confirmed (M12 plan):** empty in AFDKO 5.0.1 too.
12. The row schema has no field for profile membership, fix id, thresholds or message codes. They are recorded
    here and in summaries; if the parity tooling needs them as data, `[[check]]` needs `profile`, `fix` and
    `params` fields.
    **Answered for M3 (our decision, 2026-10-09):** profile, fix and thresholds live in the `audit`
    crate's registry as data. Inventory fields for them wait for M12 (open decision D9).
13. Naming clash: `audit.compareFamily` (AFDKO-style family checks) against the existing `window.compareFamily`
    panel (attribute table across open documents). Either rename ours (for example `audit.checkFamily`) or show
    its results inside that window.
   **Answered (M12 plan, our decision):** the id stays `audit.compareFamily` for the command line; its label is Check Family and its results go to the Font Audit panel, never to the Compare Family window (guess on the row).
