# M2 plan: compile core and the oracle harness

_Planning pass of 2026-10-08. Status: **accepted by the owner 2026-10-08**; one agent. **Done
2026-10-09**: every package built and every measure in § 5 met._

M2 turns the M0 compiler (static TrueType from the first master, components flattened) into a
static compiler for TrueType and CFF fonts that matches the reference compilers table by table,
and builds the harness that measures that. From here on, compiler correctness is a number.

## 2. What the planning pass found

- **The oracles are installed** (fontc 1.0.0, fontmake 3.12.1 with fontTools). AFDKO is not; it
  is needed only for the makeotf comparison of the CFF path, and fontmake covers CFF until then.
- **What the oracles can compile from the corpus.** fontc reads `.glyphs` versions 2 and 3 and
  designspace, and rejects version 4. glyphsLib (fontmake's reader) does not read version 4
  either (M2.0 checked: it fails on every version 4 file with outlines). Version 4 sources the oracles cannot read are compared only
  through FontCraft's own read-back. fontc's test data (about 160 sources,
  each one behaviour) and Oswald are the first comparison set.
- **The M0 compiler flattens components and reads only the first master.** Both change in M2.
- **write-fonts** has every core table writer except CFF; nothing in fontations writes WOFF or
  WOFF2 (`docs/spec/40-compile.md` § 2).

### M2.0 Oracle harness

1. Compile a source with FontCraft and with the oracle, same options, fixed `SOURCE_DATE_EPOCH`.
2. Read both fonts back and compare per table, normalised: checksums, timestamps and offsets
   removed; name records compared as a set; cmap as mappings; hmtx as advances and side
   bearings; glyf and CFF as decoded outlines within half a unit; OS/2, hhea, head, maxp, post
   field by field.
3. Report per table: identical, equivalent (differs only where normalisation allows) or
   different, with the first differences. An allow-list (`crates/oracle/allow.toml`) records
   accepted differences, each with its reason.
4. `fontcraft-cli oracle SOURCE…` for one or more sources; `--corpus` for the corpus; `--json`.
   Oracle tests in the gate are opt-in and skip when a tool is missing (`docs/testing.md`).

**Progress: done (2026-10-08).** `crates/oracle` (L3) and `fontcraft-cli oracle`.

How the two builds are made the same:

| Source | FontCraft builds | The reference builds |
|---|---|---|
| single-master `.glyphs`, `.glyphspackage`, `.ufo` | its one master | fontc: the source as it is. fontmake: `-o ttf` (or `otf`), the source as it is |
| multi-master `.glyphs`, `.glyphspackage` | the variable font origin (the harness moves it to the front, because the M0 compiler builds the first master) | fontc: a variable font, compared at its default location (fontc has no option for a static master). fontmake: `-o ttf` without `-i` writes one static font per master; the harness takes the origin's file |
| `.designspace` | its first master, which is the first source | fontc: the first source's UFO on its own (static). fontmake: `-m`, the first source's output file |

Options on every reference build: `SOURCE_DATE_EPOCH` fixed (default 1700000000), production
names on (FontCraft writes them from M4.2; `post` compares the names), and the build folder inside a
work folder. fontc also
gets `--skip-features`: FontCraft compiles no features until M8, and layout tables are not
compared. fontmake gets `--keep-overlaps` (fontc never removes overlaps; FontCraft does from M3)
and, for CFF, `--optimize-cff 1` (specialised charstrings, no subroutines, as § 3 plans for our
writer). fontmake has no option to skip features, so a feature file it rejects stops its build.

Normalisation and the report are described in `docs/testing.md` › The oracle harness. Glyphs
are matched by name. A glyph set or order that differs is reported once as a source-reading
difference; the per-glyph tables then compare the glyphs both fonts have.

### M2.1 Pipeline and resolved projection

- `Font::resolve(master or instance)`: the glyph set to export, layers at that location,
  components and their transforms, metrics and names: what every table builder reads. Nothing in
  the compiler reads `Extra` (`docs/spec/30-source-formats.md` › Compiler view).
- Preflight: missing components pruned with a warning, non-exported glyphs removed and inlined,
  glyph count limit, cmap conflicts.
- Glyph order: the model's order, `.notdef` first, synthesised when absent.
- Outline preparation in the filter order: decompose (mixed glyphs, transforms beyond ±2.0, all
  components for CFF), cu2qu for TrueType, direction, rounding.

**Progress: done (2026-10-08).** The compiler runs in stages, each a function of what the
stages before it produced:

| Stage | Where | What it does |
|---|---|---|
| Resolve | `Font::resolve(&Target)` in `crates/model/src/resolve.rs` | `Target::Master(id)` or `Target::Instance(i)`: the glyphs in the font's order with contours (Bézier paths, closed contours ending with an explicit line back to the start, as fontc builds them) and components (glyph name, transform), widths, anchors, code points, export flags, production names; the metrics, the style name, the font's properties and enabled parameters with the master's and then the instance's in their place. No `Extra` |
| Preflight | `crates/compile/src/preflight.rs` | missing components dropped with a warning (first, as fontc does); component cycles and chains deeper than 32 refused; non-exported glyphs inlined where used (contours transformed, reversed under a mirroring transform; their components kept with combined transforms), then removed; a code point on two glyphs refused, naming both |
| Glyph order | `order.rs` | the font's order, `.notdef` moved to glyph 0 or drawn as fontc draws it (a hollow box half an em wide, stroke 5% of the em, descender to ascender); more than 65,535 glyphs refused |
| Outline preparation | `outline.rs` | decomposition of mixed glyphs, of composites with a 2×2 value outside −2 to 2, and of every composite for CFF; other composites kept. A decomposed glyph keeps its own contours first, then its components' in breadth-first order, and glyphs decomposed themselves are decomposed first (fontc's order). cu2qu at 0.001 em (kurbo's `cubics_to_quadratic_splines`, the port fontc uses); contours reversed for TrueType unless `keep_direction` |
| Builders, assembly | `build.rs` | `glyf` with composites (`ROUND_XY_TO_GRID`, offsets rounded half up, F2Dot14 transforms), composite boxes from the written points as fontc computes them, `maxp` composite limits, side bearings and the font box from the written glyphs; the other tables as in M0 until M2.2 |

Decisions:

- **Resolve lives in the model.** It reads every part of the font and nothing outside it, so
  layering allows it there, and the engine and the oracle can ask for it without the compiler.
  The compiler's own choices (what to decompose, the order, the defaults) stay in
  `crates/compile`.
- **An instance between masters is an error** (`BetweenMasters`) until M9; an instance of kind
  `variable` is `NotStatic`. An instance exactly at a master uses that master's layers.
- **Alternate and intermediate layers are not compiled.** At a master's location the master
  layer is the drawing; the result's notes say how many glyphs have alternate layers (they
  become glyphs with feature variations in M8/M9). A glyph with no layer for the master is
  written empty, with a note.
- **A font with nothing to export builds**: glyph 0 alone, as fontc builds it.
- **Glyph order before outline preparation.** fontc decides both in one step; the result is the
  same, and the order is final before any glyph id is used.
- **Rounding** is half up (`floor(v + 0.5)`) everywhere: points (by write-fonts when the glyph is
  written), component offsets, advances. The M0 compiler rounded half away from zero.
- **Never crash.** Cycle and depth checks run on an explicit stack; decomposition, inlining and
  composite boxes work under a budget of `MAX_OUTLINE_ELEMENTS` per glyph (a glyph using a glyph
  that uses the one below twice, 30 levels deep, is an error at once); component counts are
  capped (`MAX_COMPONENTS`); what decomposition and inlining create over the whole font is capped
  too (`MAX_EXPANDED_ELEMENTS`, ten million segments); component offsets are held to
  `MAX_TT_COORDINATE`. The engine's
  `file.exportStatic`, the CLI's export and the oracle's FontCraft side all go through
  `compile`; the oracle asks for the variable font origin as a `Target` instead of reordering
  the masters.

### M2.4 Containers (`crates/container`)

WOFF 1 writing (per-table zlib, as M1 reads it). WOFF2 writing and reading: the table directory
with known-tag indices, the glyf/loca transform, the optional hmtx transform, Brotli. Read back
by our own decoder and compared with the uncompressed font; checked against fontTools' WOFF2
reader.

M2.4 is split in two: M2.4a, the crate with WOFF 1 and untransformed WOFF2, and M2.4b, the WOFF2
table transforms and WOFF2 opening.

**M2.4a: done (2026-10-08).** `crates/container` (L0, no workspace dependencies) wraps an sfnt
font and unwraps it again:

- `woff::encode` / `woff::decode`: WOFF 1.0, as fontTools writes it (`ttLib/sfnt.py`, the
  reordering in `TTFont.save`). Table data in fontTools' recommended order, the directory sorted
  by tag, zlib level 6 per table (stored raw when that is not smaller), `head` always raw,
  `checkSumAdjustment` for the sfnt the file unwraps to, the header version from
  `head.fontRevision`, the metadata compressed at level 6, the private block on a 4-byte
  boundary. zlib is `miniz_oxide` (already used by `crates/decompile`).
- `woff2::encode` / `woff2::decode` with `Options::untransformed()`: WOFF2 with the null
  transform on every table, as fontTools' `WOFF2Writer` writes it with
  `transform_tables=set()`: `DSIG` dropped, bit 11 of `head.flags` set, tables sorted by tag,
  `checkSumAdjustment` for that layout, the known-tag indices, UIntBase128 lengths, Brotli
  quality 11, window 22, font mode (`brotli` crate); metadata in text mode.
- A WOFF2 file with transformed `glyf`/`loca` or `hmtx` reads up to its directory
  (`woff2::directory`) and then fails with `Error::Unsupported`. Asking `woff2::encode` for a
  transform on a TrueType font (the default `Options`) fails the same way; on a CFF font the
  transforms do not apply, so the default works.
- Collections (TTC to WOFF2) are refused in both directions: our compiler does not write
  collections before M12, and the collection directory is not needed until then.
- Limits: `MAX_SFNT` (256 MiB, the stated font size and the sum of table lengths),
  `MAX_TABLES` (1,024), `MAX_METADATA` (16 MiB). Decompression stops one byte past the stated
  size. Tables may not overlap, must start on 4-byte boundaries (WOFF 1) and must lie in the
  file; the length in the header must equal the file's.
- `crates/decompile` now reads WOFF 1 through the crate (its own `woff.rs` is gone; the
  container crate is L0 and decompile L3, so the reader belongs in the lower crate and both
  directions live in one place). Its `woff_directory` and `woff_to_sfnt` stay as thin wrappers
  for `tables.list` and `font.inspect`.

**M2.4b: done (2026-10-09).** The WOFF2 table transforms, both ways, and WOFF2 opening:

- `woff2/glyf.rs`: the `glyf`/`loca` transform (version 0), ported from fontTools'

### M2.10 Export-time parameters (builder, wave 3)

Ten export-time parameters are stored but no crate reads them. In `crates/compile`: Post Table
