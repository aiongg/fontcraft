# M7 plan: Font Info and custom parameters

_Planning pass of 2026-10-11. Status: **accepted**, with the answers in § 7 decided by the orchestrator on the owner's behalf._

M7 makes the font's metadata editable and makes the custom parameters that no earlier milestone
owns take effect. It adds the Font Info window with its Font, Masters, Exports, Other Settings
and Notes tabs and their 51 commands (fields and their languages, custom parameters, masters,
metric and stem definitions, export entries, settings, the note, row copy and paste, scaling to a
new UPM); a catalogue of all 205 custom parameters with their value kinds, scopes and aliases;
text tokens; projects; and, at export, the name parameters, the glyph-set parameters (Remove,
Keep, Export, Rename and Reencode Glyphs, Arabic presentation forms), the Filter and PreFilter
strings, Scale to UPM, Export Folder, the legacy `kern` table and linked sources (Import Font,
Import Master).

The plan is cut for wide fan-out: M7.1 lays down the new crate `fontinfo` and every module's
public signatures with empty bodies; after it, 12 packages can be written at once in worktrees,
and none of them needs anything from M6 (§ 6).

## 3. Answers and decisions

### Design decisions (new questions of this pass)

| Question | Answer for M7 |
|---|---|
| Where Font Info logic lives | A new crate `fontinfo` (L2: `model`, `plist`, `geom`): the parameter catalogue and value checks, the General field catalogue, master and instance addressing (`id`, name or index), the row clipboard format, text tokens, the scaling of a font to a new UPM, and the parsers of the glyph-set parameters. Pure functions, no I/O. The compiler, the engine and the UI use it |
| The parameter catalogue | Generated from the inventory's parameter rows (all chapters, 205 custom parameters and the built-in fields) by `cargo xtask paramcatalog` into `crates/fontinfo/src/catalog_data.rs`, checked in, with `--check` in the gate's spec step. Each entry: name, aliases (short and UFO long spellings), kind, stated scopes, effect, owning milestone, whether it is measured in units, whether it may repeat, and a one-line description from the row's summary (three summaries that name vendors get a `picker` text of their own, a field M7.2 adds to `xtask/src/spec.rs`, so `cargo xtask brands` passes) |
| Where a parameter may be set | Its stated scopes; a parameter whose entry states none is allowed on the font, masters and exports (guess). Name properties live in `properties`, not in the parameter list: `font.customParameters.add` with a property key writes the property (the picker lists them under their plural names) |
| Value checks | Every add and set checks the value against the kind (bool, number, string, list, dict, localized text) and the parameter's own syntax where the catalogue has one (Name Table Entry, Remove Glyphs, Rename Glyphs, Reencode Glyphs, Filter, versionString); a wrong value is refused and nothing changes. Values read from files are not checked on opening: export reports the ones it cannot use |
| Precedence | Export over master over font, as the model's resolution already does; Name Table Entry entries add up over the levels (fontmake) |
| Commands address targets | `scope` plus `targets` (`id`, name or index), as the rows give; an ambiguous name is refused naming the ids. Several targets get the same value in one undo step |
| Export-time parameters | Two stages. **Engine** (`engine/src/export_steps.rs`, before the compiler, on a copy of the font): linked sources, PreFilter, Scale to UPM, Filter (with components decomposed first), Export Folder. **Compiler** (`compile/src/export_params.rs`, after resolving): Export, Keep, Remove, Rename and Reencode Glyphs and Arabic presentation forms, which change the resolved glyphs and hand a rename map to the kerning writer; then names (`info.rs`) and the legacy `kern` table (`kern_table.rs`). The CLI, the control channel and the oracle harness all export through the engine, so both stages run for every export |
| Where no oracle reads a parameter | The handbook, with every choice of ours a guess on the row (owner's rule) |
| Where the handbook and an oracle conflict | The oracles decide compiler questions (`AGENTS.md`), except where § 7 question 2 asks the owner: postscriptFullName to name ID 4, instance Width Class to OS/2, Macintosh name records by default |
| Name ID 5 | `Version <major>.<minor>;FontCraft <version>`, as the handbook and fontc write it (fontc with its own name); an export option leaves the suffix out; the oracle comparisons ignore the suffix. `docs/spec/40-compile.md` already allows the stamp |
| Projects | A project document of its own kind in the engine, saved in a native project format until the reference app's format can be read from a sample (§ 7 question 3); its export runs the same build as File › Export with the project's instances |
| Linked sources | Import Font and Import Master are resolved when a document opens and before each export: the referenced file is read, its glyphs (or master) are added to the document's font marked as linked and locked, and the source writers leave linked glyphs and masters out. No nesting: a linked file's own Import Font is ignored with a warning |
| Font Info window | `ui-egui/src/shell/font_info/`: one module per tab, a shared row module and a value editor per parameter kind; every control acts through `app.run`. One window per document |
| Undo | Every font-changing command is one undo step; a refused command leaves the font pointer-equal |

### Limits (never crash)

| What | Limit |
|---|---|
| Custom parameters per scope; properties per scope | 4,096; 1,024 |
| Languages of one localized field | 256 |
| One field's text | 65,535 bytes (the compiler still cuts name strings at its `MAX_NAME_CHARS`) |
| One parameter's value | 4 MiB of text; lists and dictionaries 65,535 items; nesting within `fontcraft_plist::MAX_DEPTH` |
| Masters; export entries; project instances | 256; 4,096; 4,096 |
| Metric definitions; stem definitions | 256 each |
| Units per Em | 16–16384; scaling refused when a scaled coordinate would leave ±32,768; factors finite |
| Weight Class; Width Class | 1–1000; 1–9 |
| Version | major 0–32,767, minor 0–999 (as M2's `font.info.set`) |
| Glyph-set entries (Remove, Keep, Export, Rename, Reencode) | 65,535 lines, each at most 1,024 bytes; a wildcard pattern holds at most 16 `*`, matched without backtracking |
| Text tokens | 1,024 tokens per field; one level (an expanded value is not expanded again); expanded text 65,535 bytes |
| Filter strings at export | 64 per instance (Filter and PreFilter together); each within M3.12's `MAX_ITEMS` |
| Linked sources | 16 Import Font and 16 Import Master parameters; each file within the readers' `MAX_INPUT`; no nesting |
| Export Folder | 32 path segments, 1,024 bytes; absolute paths refused |
| Legacy `kern` table | 10,920 pairs per subtable, 65,535 pairs in all (the rest dropped with a warning) |
| Row clipboard | 4,096 rows, 4 MiB |
| Master icon glyph | the glyph's outline drawn within `MAX_OUTLINE_ELEMENTS` |

### Guesses

Every choice of ours where no source says what the reference does is in a row's `guesses`: 66
entries on 57 M7 rows, all new. With them the inventory goes from 678 guesses on 435 rows to 744
on 492. `docs/parity.md` and `docs/guesses.md` are not regenerated by this pass (M7.0 does). Each
guess names what would settle it, and § 8 lists the step in the reference app. The ones with the
most effect:

- Parameters: allowed scopes, duplicates, empty values, unknown parameters:
  `font.customParameters.add`, `fontInfo.customParameterPicker`, `customParameters.unknownKept`.
- Fields: the General field lists, adding a present field, languages, copy and paste:
  `font.info.listFields`, `font.info.addField`, `font.info.setLocalizedValue`,
  `font.info.copyRows`, `font.info.pasteRows`.
- Scaling: what is scaled and how it rounds: `font.info.scaleToUnitsPerEm` (also used by Scale
  to UPM).
- Masters and exports: defaults of new entries, what a removed master takes with it:
  `font.master.add`, `font.master.duplicate`, `font.master.remove`, `font.instance.add`,
  `font.instance.setStyleLinking`.
- Export: removed bases decomposed, Keep with Remove, Rename to a missing name, Filter
  decomposing composites, presentation forms, the kern table layout, Name ID suppression,
  Macintosh and compatible records, `%d` templates: `Remove Glyphs`, `Keep Glyphs`, `Rename
  Glyphs`, `Filter`, `Use Arabic Presentation Form Unicodes`, `Export kern Table`, `Prevent Name
  ID`, `Export Mac Name Table Entries`, `Compatible name Table`, `versionString`.
- Projects and linked sources: the native project format, path forms, missing files:
  `file.newProject`, `project.linkFont`, `Import Font`, `Import Master`,
  `export.instanceExportFolder`.

"worktree" packages run in parallel without builds or tests; each runs one compile check before
it commits, and the orchestrator builds, tests and sends back errors. "builder" packages run in
the main checkout, one at a time, behind M6's builder packages. Every package registers its
commands with a one-line edit to `cmd/mod.rs` or the shell's module list, merged by the
orchestrator. Each package edits only its own rows' `notes` and `guesses` when behaviour turns out
different, and names the change in its report. Tests are written as behaviour tests on fonts built
in code; the worktree agent writes them blind and the orchestrator runs them.
