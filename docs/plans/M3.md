# M3 plan: Edit View drawing

_Planning pass of 2026-10-09. Status: **accepted by the owner 2026-10-09** (§ 7). M3.0 done
2026-10-09: the spec pass and decisions are in the inventory and the notes._

M3 turns Edit View from a glyph viewer into an outline editor. It adds the pointer tools, a
selection, node and path editing, transformations, the path-operations engine (which also gives
static export its overlap removal), guides, backgrounds, filters and the outline checks. It also
gives agents the means to drive and see the editor: `ui.pointer`, `ui.key` and `ui.screenshot` on
the control channel.

## 1. Scope

495 inventory rows name M3: 210 commands, 194 behaviours, 34 checks, 21 tools, 20 panels,

`view.zoomOut`, `view.zoomToActualSize`, `view.showNodes`, `view.showMetrics`, `window.palette`).

## 2. What the planning pass found

- **Rows by area and status.** Status of the 495 rows: 366 `handbook`, 69 `docs`, 56 `inferred`,
  4 `memory`, 0 `observed`. By area: drawing 174, path-ops 127, guides-metrics 59, qa 54, layers 34,
  ui-chrome 32, import-export 10, edit-text 3, compile 1, automation 1. By chapter file: `03a` 149,
  `04-palette` 69, `03b` 67, `11-filters` 58, `21-qa-checks` 54, `90-secondary` 42, `05-font-view`
  18, `07-import-export` 13, `18-custom-parameters` 11, `06-font-info` 5, `00-app-basics` 4,
  `30-formats` 4, `10-interpolation` 1.
- **The model already holds what M3 edits.** Nodes carry `smooth`, `locked` and type; paths carry
  a lock, stroke attributes (width, height, position, caps, joins, fill) and a mask; glyphs carry
  a lock; layers carry local guides, annotations, a background and an image; masters carry
  global guides and user data; font info carries the grid (`grid_length`,
  `grid_sub_division`). M3 needs no new model fields. It needs helpers: segments with node
  addresses, address resolution, and grid rounding.
- **The engine lacks five things M3 depends on.** Explicit addresses for points and shapes; an
  interaction (a drag previews many times and commits once); a query that returns a layer's
  outline with addresses; a way for the shell to know what a command acts on (to grey it out and
  fill its targets from the selection); and the `when` and `context` fields of decision 0004
  item 5.
- **The UI shell is small** (`crates/ui-egui/src/app.rs`, 378 lines). Shell commands are one
  shared constant list (`UI_COMMANDS` in `menus.rs`), so every package adding a view command
  would edit the same lines. The menu tree is rebuilt every frame, which `docs/status.md` lists
  as due in M3.
- **kurbo 0.13 already provides** stroking (`stroke`), curve offsetting (`offset`), curve fitting
  (`fit`), simplification and SVG path parsing. Expand Outline, Offset Curve, the Pencil and the
  refit after Delete build on it.
- **Booleans.** `docs/references.md` plans linesweeper 0.5 (MIT OR Apache-2.0) for curve booleans.
  It is not yet a dependency. Overlap removal must be robust enough to be on by default for
  static export (`docs/spec/40-compile.md` § 3.8), so M3.6 starts by measuring it on the corpus.
- **Screenshots.** The build machine has lavapipe (software Vulkan), so the desktop app renders
  on a virtual display. eframe can capture the rendered window; no extra renderer is needed for
  `ui.screenshot`.
- **The four `memory` rows** are `edit.cut`, `edit.copy`, `edit.paste` and `path.convertToCubic`.
  `path.convertToCubic` is confirmed by the handbook row `fontView.batch.convertToCubic` (menu
  Path › Other) and becomes `handbook`. Cut, copy and paste exist in the handbook (Edit › Paste in
  `paste.vectorOutlines`, copy and paste as the alternative to Option-drag in 03a § 11); the
  clipboard flavours their summaries describe are our design, so they become `inferred`.

  - `path.convertToCubic`: `memory` → `handbook`, ref "Font View › Batch-Processing".

  - `dialog.export`, `dialog.exportOtf`, `dialog.chooseExportFolder`, `export.removeOverlapOption`:

### New questions from this pass

| Question | Answer for M3 |
|---|---|
| How does a command name a point? | A target object: `{glyph, layer, points?: [[shape, node]…], shapes?: [index…], anchors?: [name…], guides?: [{scope: "local" \| "global", index}…], annotations?: [index…]}`. Indices are positions in the layer's lists. An address that does not resolve is an error, and the command changes nothing. Counts are capped like `path.addPath`'s nodes |
| What is the selection after an edit? | Every command that changes structure returns `selection` in the same shape, with the new indices. The shell replaces its selection with it. After undo or redo the shell drops entries that no longer resolve |
| Where does the selection live? | In `UiState`, per tab, serialisable. The engine never stores it. `selection.*` and `edit.selectAll` style commands are shell commands |
| How is a drag one undo step? | `Session::begin(label)` takes a snapshot; `preview(id, params)` runs a command on the snapshot without recording history; `commit()` records one undo step and journals the last command and parameters; `cancel()` restores the snapshot. Dialog previews use the same mechanism |
| How does the shell know what a command acts on? | `CommandSpec` gains a `targets` field (`layer`, `points`, `paths`, `anchors`, `guides`, `glyphs`). One function in the shell fills those parameters from the selection and greys out the menu item when the selection has none |
| Grid rounding | Engine commands that create or move points round them to the font's grid (spacing ÷ subdivision; spacing 0 means no rounding). Tools pass unrounded coordinates. Agents get the same result as the pointer |
| Screenshots | `ui.screenshot` asks eframe for the rendered window and writes a PNG. Headless tests keep checking drawn shapes in a bare egui context; glyph pixels are checked with `ui.render`, which uses the `render` crate |
| Rasteriser for `render` | tiny-skia (BSD-3-Clause) with PNG output. It builds for wasm |
| Boolean library | linesweeper. M3.6 first runs overlap removal over every corpus glyph layer. If it fails the measure in § 5, the package reports to the owner before choosing another library |
| SVG reading | usvg (MIT OR Apache-2.0) for import and paste, behind the guard, with a size limit on input. Writing SVG (copy) is our own code: paths only |
| System clipboard | The engine never touches it: `edit.copy` returns the clipboard data, `edit.paste` takes it. The desktop shell moves text through arboard (MIT OR Apache-2.0) |
| Menu tree per frame | Cached per document revision and per selection change (M3.2) |
| Shell command list | `UI_COMMANDS` becomes one list per module (as `cmd/mod.rs` does for engine commands), so parallel packages add modules instead of editing one list |

| 03a.2 Nudge with keys ▶ | `Ctrl+Alt` with an arrow key nudges, with the arrow increments (1, 10, 100) |
| 03a.3 Draw tool on a segment ▶ | A plain click on a segment inserts a node at the click; a click on an open end node continues that path; `Escape` or another tool ends the path |
| 03a.4 Draw tool `Shift` | Constrains the new node or handle to 45° steps from the previous node |
| 03a.5 Primitives dialog ▶ | Width and height, created with the click as the lower-left corner; the ellipse has four nodes at its extremes; values are remembered for the session |
| 03a.6 Erase; Rotate and Scale buttons | Erase deferred (§ 1). Rotate and Scale are separate tools with `R` and `S`, as their rows say |
| 03a.7 Marquee and segments | A marquee selects the handles inside it whatever their node; clicking a segment selects its two end nodes |
| 03a.8 Tab order | Nodes in path order, then the next path, then anchors, then guides, then wrap |
| 03a.9 Corner to smooth ▶ | Missing handles are added at one third of the segment; two handles that are not collinear are turned to the bisector of their directions, keeping their lengths. Tidy up classifies a node as smooth within 1° (the `kinkedSmoothNode` threshold) |
| 03a.10 Delete with refit | The new segment is fitted to the removed segments with kurbo's curve fitting, within 0.5 unit. Only handles selected: the segment becomes a line. Every node of a path selected: the path is removed |
| 03a.11 All-masters variants | Nodes are matched by address. A layer whose structure differs is skipped and listed in the result (`skipped: [{layer, reason}]`). Alternate and intermediate layers are included only by Correct Path Direction, as the handbook says |
| 03a.12 Super-smooth | Deferred (§ 1) |
| 03a.13 Align Selection | A tie between width and height aligns on one X. The transformation origin's column or row picks min, centre or max. Handles of smooth nodes move with their nodes |
| 03a.14 Open Corner | Overlap of half the master's first vertical stem and half its first horizontal stem; 20 units when the master has no stems. The invisibility threshold stays open; overlap removal at export takes the small triangle away |
| 03a.15 Reconnect ties | Lower address first |
| 03a.16 Correct Path Direction | Outer contours counter-clockwise, counters clockwise (decided by winding of the nesting); shapes sorted by bounding box (left, then bottom); start node is the lowest, then leftmost on-curve node (the `startPointPosition` rule) |
| 03a.17 Add Extremes | An extreme is skipped when it would leave a segment shorter than 3 units (the `shortSegments` threshold). A node within 2 units and 2° of an extreme is moved onto it (the `almostOrthogonalHandle` thresholds). Targets as given, default the whole layer |
| 03a.18 Labels of alternates | "… for All Masters", with the shortcuts the rows give |
| 03a.19 Path focus | Per tab; cleared when the edited glyph changes |
| 03a.20 Locks | Stored in the file (the model and both formats hold them). A glyph lock refuses every command that changes the glyph's own data: layers, outlines, anchors, guides, width, metrics keys. Kerning is font data and is not blocked |
| 03a.21 Stroke ▶ | Joins: miter, round, bevel, round full. Caps: butt, round, square, round inset, axis-aligned. Positive position is to the right of the path direction. Butt, round, square, miter and bevel come from kurbo's stroker; round inset, round full and axis-aligned are our construction. Export expands strokes; interpolation is M9 |
| 03a.22 Pen points | Deferred (§ 1) |
| 03a.23 Mask | A mask subtracts from every shape below it, components included (decomposed for the operation); stroked shapes are expanded first; export applies masks during outline preparation |
| 03a.24 Shape Order dialog | One row per shape (kind, component name or path index, a thumbnail); acts on the current layer |
| 03a.27 Guides ▶ | `Delete` removes the selected guide (`guide.remove`). Dragging off the knob rotates about the knob. Angle-locked guides move but do not rotate. Sidebearing reference: left keeps x, right moves with the width, both keeps the guide's fraction of the width. Guides are snap targets |
| 03a.28 Snapping ▶ | Snap distance 4 screen points (a token). Priority: nodes, handles, guides, metric lines. `Ctrl` suspends snapping and magnetic guides |
| 03a.29 Undo | D4 above |

#### Spike result

**Recommendation: go**, with the input rules below. On the corpus linesweeper matches the
reference everywhere and is well inside the speed target. On random paths it still has a rare
hang and a rare failed assertion, which must be fixed upstream or worked around before overlap
removal runs by default at export (M3.7).

Setup:
- linesweeper 0.5.0, MIT OR Apache-2.0, the latest release on crates.io. It is the only new
  dependency.
- `cargo xtask overlap` runs `fontcraft_pathops::union` (nonzero union) on every glyph layer of
  the comparison set that has closed paths. Components and open paths are left out.
- `crates/pathops/crosscheck/reference.py` runs skia-pathops 0.9.2 on the same inputs, the way
  fontTools' `removeOverlaps` calls it: `simplify`, nonzero, outer contours counter-clockwise.
- Coverage is the § 5 rule: nonzero, 1 px per unit, exact across a row, 16 sub-rows per pixel.
- Times come from the dev profile, where dependencies build at opt-level 2.
- `--quadratic` converts every input to quadratic curves first (tolerance 1 unit), so the
  quadratic form is measured as well.

| Measure | Cubic input | Quadratic input |
|---|---|---|
| Sources / layers / layers with closed paths | 354 / 5,337 / 2,368 (6 sources fail to load in our readers, as before) | same |
| Panics, errors, hangs | 0, 0, 0 | 0, 0, 0 |
| Result vs input (§ 5: ≤ 0.5 per pixel, ≤ 0.5% of ink) | 2,368 of 2,368; worst 0.044 per pixel, 0.007% | 2,368 of 2,368; worst 0.036, 0.005% |
| Result vs skia-pathops, same rule | 2,368 of 2,368; worst 0.063 per pixel, 0.005% | 2,368 of 2,368; worst 0.024, 0.009% |
| Second run changes nothing (same coverage and points) | 2,368 (2,112 identical to the bit; the rest move by the input grid below) | 2,368 |
| Orientation consistent (signed area = covered area) | 2,368 | 2,368 |
| Time per layer, ours | median 40 µs, p99 405 µs, max 726 µs | median 42 µs, p99 410 µs, max 782 µs |
| Time per layer, skia-pathops | median 14 µs, p99 97 µs, max 178 µs | median 14 µs, p99 80 µs, max 118 µs |
| On-curve points vs skia-pathops | 2,270 same, 64 more, 34 fewer | 2,085 same, 78 more, 205 fewer |

Quadratic input stays quadratic: every result segment is a piece of an input segment of the
same kind. "More points" are points left on a straight line where two contours merged (for
example where a descender joins a stem). skia-pathops removes every such point.

Random paths (the plan's generator: up to 64 segments of lines, quadratics and cubics, with
points from four grids, many of them shared), with the input rules below:

| Run | Panics | Hangs (> 10 s) | Slowest finished case |
|---|---|---|---|
| The plan's test, 10,000 cases (ignored test in `crates/pathops`) | 0 | 0 | under 1 s |
| 100,000 cases | 0 | 1 | 139 ms |
| 20,000 cases on each of the four grids (80,000) | 1 (whole units) | 1 (whole units) | 191 ms |

Without the rules, 80,000 cases gave 15 panics, 13 of them on points closer than linesweeper's
tolerance. The one panic left is a `debug_assert!` in `Topology::contours` (a winding that
should be inside is not); a release build skips it and may return a wrong outline for that case. The hang is an endless loop without allocation in `Topology::contours`, after the
sweep. The smallest case found has two contours, 7 segments, whole-unit coordinates and one
horizontal line; tilting that line by one unit removes the hang:

```
M648,-423 C162,713 -615,-1 983,-825 C-978,621 216,-353 -245,468 Q493,57 -673,-576 Z
M-902,239 C-219,-93 -41,59 169,-315 L254,-315 Q-374,-844 273,247 Z
```

What raw linesweeper does with hostile input:

| Input | Result |
|---|---|
| A NaN coordinate | panic (assertion in `segments.rs`); `binary_op`'s own check misses it, because the bounding box drops NaN |
| An infinite coordinate | `binary_op` refuses it; with a tolerance passed by hand, a wrong outline |
| A contour at 1e20 next to one of 100 units | the small contour disappears (the tolerance grows with the largest coordinate) |
| Coordinates near 1e300 | contours with NaN area |
| An open subpath | an error |
| Zero-length lines, collapsed cubics, single-point and two-point contours, duplicate and cancelling contours | correct |
| A contour smaller than 1e-6 units | dropped |
| One contour with about 80,000 crossings; 200 overlapping circles | 357 ms; 335 ms |
| A cubic that crosses itself, alone in its contour with a closing line | panic (`topology.rs`, a result contour made of one input segment) |

Rules the `pathops` crate applies (the spike's `prepare` and `union` already do 1 to 5):
1. Every coordinate is finite and within ±1,000,000 units, the model's limit; otherwise refuse.
   Below that limit linesweeper's tolerance stays at 1e-6 units.
2. At most 100,000 segments per operation.
3. Only closed subpaths go in. Open paths are set aside; what Remove Overlap does with them is
   to be observed in the reference app.
4. Input points are rounded to 1/1024 unit, so that two points are either equal or further
   apart than the tolerance.
5. A curve that crosses itself, including one that ends on its own start, is split at the
   parameter halfway between its two crossing parameters.
6. Result points closer than 0.001 units are merged (linesweeper can return one intersection
   twice, 1e-12 units apart).
7. When results become nodes: drop the explicit closing line, round to the font's grid
   (intersections are not on any grid), and keep the input's start points where they survive
   (linesweeper picks its own). Points the operation leaves on a straight line go; a node the
   designer drew on a straight line and a kept start stay (M3.30).
8. Every call runs under `fontcraft_engine::guard`. Until the hang is fixed, native callers that
   remove overlaps without a person waiting (export, batch commands) run each glyph on a worker
   thread with a time limit and report the glyph. In the browser there is no such limit.

The hang and the assertion are also present in linesweeper's main branch at the time of the
spike (its source matches 0.5.0). The owner decided to keep linesweeper from crates.io, not to
report the cases upstream for now, and to rely on rules 1 to 8: overlap removal at export
(M3.7) runs with the time limit of rule 8. The other permissive engines are polygon-only (curves
would have to be flattened and refitted), so a time limit is cheaper than switching libraries. A
newer release is measured again with `cargo xtask overlap` and the random-path test before it is
taken.

### M3.19 Drag modifiers of the Select tool (writer, wave 1; built)

Four handbook drag gestures behave wrongly. `Alt` on a handle sends `mode: "pointsOnly"`;
`Ctrl+Alt` on a handle of a smooth node uses a new `selection.move` mode `mirror` (the opposite
handle takes the same length at the opposite angle). `Alt`-drag on a segment runs a new
`path.reshapeSegment {glyph, layer?, segment, t, to}`, which keeps both handle directions and
solves the two handle lengths so the point at `t` lands on `to` (a 2×2 linear system; singular or
negative lengths clamp to a minimum; lines are left alone). `Alt`-drag on nodes with no copyable
part moves them as points only instead of duplicating nothing.

Rows: `move.handles`, `move.mirrorHandleAcrossSmoothNode`, `move.dragSegment`,
`duplicate.optionDrag` (partly). Needs: none.

Files: `crates/tools/src/select.rs`, `crates/tools/src/selection.rs`, `crates/engine/src/cmd/node.rs`
(mode `mirror`), new `crates/engine/src/cmd/segment_reshape.rs`; `03a` rows.

Tests: tools event sequences per gesture → invocations; engine: mirror on smooth and corner
nodes, reshape hits `to` at `t`, undo restores, bad parameters are named.

Guesses: the segment solve; a lone node under `Alt`-drag moves as points only.

Observe: `Alt`-drag one node; `Alt`-drag a curve segment at its middle and near an end.

Built in wave 1 (M3.19, X.fix73): the segment solve is damped for nearly parallel handles and keeps both
lengths within limits; a handle moved onto its node leaves the opposite handle alone. Left: off the Mac a
Ctrl-drag also turns on the lever (Ctrl reports as Cmd).

### M3.34 Offset Curve, Make Stroke, Round Corners vs skia-pathops (builder, after the waves; written, measure to run)

The stroke-based filters have no oracle. A new `crates/pathops/crosscheck/stroke.py` and `xtask
offset` check, per corpus layer, that Offset Curve +d equals the glyph united with skia-pathops'
mitred stroke of width 2d, −d the glyph minus it, and Make Stroke at 50% equals skia's stroke for
every cap and join. Fixes include at least: compatible-stroke parts go through overlap removal
unless Keep Compatible is on; loops on tight curves are removed; Round Corners handles corners
next to quadratic segments (raise to cubic, round, convert back); Rounded Font picks the vertical
stem nearest each stroke ending's width.

Rows: depth of `filter.offsetCurve.*`, `stroke.joinsAndCaps`, `filter.roundCorners`,
`filter.roundCorners.visualCorrections`, `filter.roundedFont.usesVerticalStems`. Needs: M3.30.

Files: `crates/pathops/src/filters/{offset_curve,round_corners,rounded_font}.rs`,
`crates/pathops/src/stroke.rs`, new `crosscheck/stroke.py`, new `xtask/src/offset.rs`.

Measure: coverage within the rule on at least 99% of corpus layers for +20, −10 and Make Stroke
30 units, the rest listed by cause; Offset Curve under 50 ms median per layer.

Guesses: mitred corners; the nearest-stem rule. Observe: Offset Curve +20 on an O and a 30°
wedge; Keep Compatible on an open path.

Written:
- `stroke.py` and `cargo xtask offset`. Skia's own stroke is wrong on tight curves: it fills the two
  edges with the nonzero rule, and where a curve turns tighter than half the width the edges cancel (a
  circle of radius 5 stroked 40 wide has area 1,261 instead of 1,963). The script therefore unites
  Skia's stroke of the whole path with its strokes of every stretch from mid-segment to mid-segment;
  the circle then comes out right (1,970 for +20).
- Offset Curve and Make Stroke had the same fault for the same reason. A curve whose offset folds over
  is also stroked as bands of at most about a quarter turn each, united with the sweep
  (`tight_bands`). Layers without such a curve take the same path as before.
- Round Corners: a quadratic spline next to a corner is taken apart into its pieces, the piece the
  corner touches is split like a cubic, the arc is a quadratic spline, and untouched implied points go
  back. (A cut piece of a quadratic is a quadratic, so no raise to cubic is needed.)
- Rounded Font without `stem`: each ending against the vertical stem nearest its width.
- Make Stroke's parts already go through overlap removal unless Keep Compatible is on; unchanged.
- Round inset and axis-aligned caps and the round full join have no reference; the harness leaves them
  out.

The reference side was run on the 1,703 layers of M3.30: 12 operations each, 20,433 results, 3 errors
(one glyph layer with round caps; Skia's union gives up). As a check on the script itself, 150 of its
round-join, round-cap results were compared with the plain distance to the path at random points: 18,891
points, none on the wrong side.

The builder runs, after M3.30's commands, with `$P` and `$O` as there:

```

cargo xtask offset --out $O/offset                        # writes layers.jsonl, prints our times
$P -I crates/pathops/crosscheck/stroke.py $O/offset/layers.jsonl $O/stroke.jsonl
cargo xtask offset --out $O/offset --reference $O/stroke.jsonl
```

Look first at the "grow" line: share equal (target 99%), median time (target 50 ms) and the causes.
"A curve of radius" left over means `folds` or `MAX_BAND_TURN` misses a case; "a corner of" means the
mitre limit is read differently (Skia's limit is the same ratio, 4); "no known cause" on smooth layers
is usually Skia: run `stroke.py --only grow` on the one layer and compare with a round join, or with the
stroke drawn at ten times the size. Then "stroke", "shrink", the nine JOIN-CAP lines (path strokes) and
the three make-CAP lines (Make Stroke on open paths). `make-butt` worse than `miter-butt` points at
Offset Curve's chain of sides, the two together at the reference.
