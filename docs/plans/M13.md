# M13 plan: plug-ins, scripting and automation depth

_Planning pass of 2026-10-11. Status: **accepted** 2026-10-11; the § 7 answers were decided on the owner's behalf, and M13.0 recorded them._

M13 gives FontCraft its extension model and the automation surfaces that remain, and builds the
secondary references' features the earlier passes moved here. The extension model is FontCraft's
own (decision 0005): commands driven over the CLI, the control channel, MCP and macros, and
sandboxed WebAssembly modules of three kinds (filter, reporter, check). The reference's Python
plug-ins and scripts do not run; § 3 maps every one of its plug-in and scripting rows onto this
model, and the rows that have no place in it are dropped (§ 7 question 2, listed in § 2). M13
also holds the caps, segments and brushes moved from M6, planned to wait for the checks in the
reference app that § 8 lists, and the source diff the M12 planner is adding, which M13's
external-changes review uses (§ 3).

### Design decisions

| Question | Answer |
|---|---|
| Module host | A new L2 crate `plugins` (deps `model`, `geom`, `serde_json`, `wasmi`), ported from VectorCraft's `crates/plugins` with credit: wasmi with the portable dispatcher, no host imports, fuel per call, a wall-clock check on native builds, a memory cap, a fresh instance per run. It builds for `wasm32-unknown-unknown`, so modules run in the web app too |
| ABI v1 | Exports `memory`, `fc_abi_version() -> i32` (1), `fc_manifest() -> i64`, `fc_alloc(size) -> ptr`, `fc_run(input, len, params, len) -> i64`, as VectorCraft's with our prefix. Manifest: `id`, `name`, `version`, `kind` (`filter`, `reporter`, `check`), `author`, `description`, `params` (the sibling apps' schema: number, int, bool, choice), `capabilities` (must be empty in v1) |
| Module input and output | Input: one layer in the native format's layer JSON with the glyph's name, unicodes, the master's metrics, the selection (filters in Edit View) and, for reporters, the view scale and whether the glyph is active. Filter output: the layer's paths, components and anchors, and an optional `log` list; checked against the model's limits before one edit applies every layer's result. Reporter output: foreground and background primitive lists (path with fill or stroke, line, circle, text; colours as RGBA; widths in screen pixels). Check output: findings (name, severity, message, optional position) |
| How modules appear in the registry | Not as new command ids. `plugin.runFilter {id}`, `view.showReporter {id}` and `audit.run` take the module id; menus list the installed modules as items that invoke these commands with the id. The command registry stays static, so `cargo xtask parity` and the command sweep keep working |
| Lock rules | Modules and macros act through the engine, so a locked glyph refuses with a message; locked and hidden paths go to filter modules and may change (handbook, `plugin.lockedPathsAndGlyphs`) |
| Where installed modules live | Per process, in the session (`ExtensionState`), not in documents. A document that names a module in an export parameter keeps the name; exporting without the module fails with a message naming it |
| Macro format (D8) | JSON `.fcmacro`: `{"format": "fontcraft.macro", "version": 1, "title", "description", "args": {…params schema…}, "requires": [module ids], "steps": [{"command", "params"}]}`. A value `{"$arg": "name"}` anywhere in a step's params is replaced by the argument; `glyphs` and `layers` are built-in arguments the shell fills from the selection. No conditionals or loops. A reader refuses a newer `version`. Command ids and parameter names follow decision 0004 item 8: renames keep aliases, and the run resolves them |
| Running a macro | `script.run` resolves every step's id and placeholders first, so an unknown command or argument changes nothing; then it runs the steps as one transaction and one undo step, like `command.batch`, and names the first failing step. A macro may call `script.run`, up to 8 levels deep; a macro that reaches itself is refused |
| Recording | `script.recordMacro` records each successful font-changing engine command from any surface (queries, UI commands, undo and redo excluded) through one hook in `Session::execute`, and writes a macro at stop |
| Command log | A ring buffer of the last 10,000 commands run from any surface, with result or error, in the session; the Command Console and `app.info` read it |
| Extension indexes | JSON `{"format": "fontcraft.extensions", "version": 1, "entries": [...]}`; entries `id`, `kind`, `version`, `titles`, `descriptions`, `vendor`, `url`, `sha256`, `size`, `homepage`, `funding`, `screenshot`. Local paths and HTTPS URLs (§ 7 question 5), HTTPS fetched by the desktop app only (the engine reads bytes the shell hands it); no main index is built in |
| Folder watching | Polling of names, sizes and modification times on focus and every 5 seconds; no file-watcher dependency, and the same code on every platform |
| Secondary features' stored data | In `userData` under `com.fontcraft.*` keys on the object it belongs to (anchor expressions on the anchor, stored selections and auto-layer recipes on the glyph or layer, contour names on the path, guide thickness, markers and power links on the guide, servant axes on nodes, statuses on glyphs and their definitions on the font, export profiles in user settings). `.glyphs` and UFO keep them. M13.1 fixes the key list in `model/fc_keys.rs` |
| Element references, delta filter, Fusion (D7) | Dropped (§ 7 question 3): neither source format can hold them and components of non-exporting glyphs, corner components and the mask attribute cover their uses |
| Auto-spacing (D11) | For each side, sample the outline's horizontal extremes every `step` units (default 5) over a band from the baseline minus overshoot to the reference height plus overshoot (x-height for lowercase, cap height for capitals and figures); clip each sample to `depth` (default 10% of the x-height) inward from the side's extreme. The side's white is the distance from the sidebearing line to the extreme plus a weight times the clipped profile's mean depth over the rows with ink; auto-spacing makes it equal to `area`. `area` and the weight are fitted per font by least squares on the control glyphs n, o and v (capitals and figures: H, O and V): a line through their six sides, white outside the extreme against mean clipped depth, gives the weight as its slope (held between 0 and 2) and the area as its value at depth 0, so a straight, a round and a diagonal side keep about their spacing. With only straight controls the weight is 1. Glyphs with metrics keys or automatic alignment keep their keys. Our own method; HT Letterspacer's documentation names similar parameters, its code is not read |
| Auto-kerning (D11) | The optical gap of a pair is taken between the left glyph's right profile and the right glyph's left profile over the same bands as auto-spacing, each clipped to its own `depth` (default 30% of the x-height) inward from its extreme. The gap is the power mean of order -2 of the row distances (each at least 1 unit), so the rows where the glyphs come closest count most. The proposed value is the target separation minus that gap, where the target is the gap of a reference pair (n n, H H) without kerning. Options from the row (minimum value, only closer, touching, keep existing); values rounded to 5 units by default. Build Kerning Groups clips at 15% of the x-height. Kern to Distance uses the exact smallest horizontal distance between the outlines instead |
| Profiles, stems, outline matching, expressions | Shared code with signatures fixed in M13.1: `spacing::profile` (M13.20 writes it; M13.21 to M13.23 use it), `pathops::stems` (M13.24; M13.34 to M13.36 use it), `pathops::matcher` (M13.15; M13.28 uses it), `geom::expr` (M13.16; M13.17, M13.23, M13.29 use it) |
| Caps, segments, brushes | Provisional fitting in the rows' guesses (§ 2 of `09-reusing-shapes.md`, Q-29 to Q-31). M13.40 to M13.42 start once the § 8 exports from the reference app's trial are in, and use them as the oracle; if the trial ends without them, they are built on the guesses (§ 7 question 6) |
| External changes and M12's source diff | `file.reviewExternalChanges` reloads the file from disk and lists glyphs, layers and font-level data that differ from the open document. It uses M12's source diff engine when that has landed, and model equality per glyph until then; `dialog.externalChanges` reuses M12's diff and merge window with the disk file as the other side if that window can take an open document and a path as its two sides. M13 asks the M12 plan for that entry point and does not edit M12's files |
| TrueType debugger | The hinted preview draws with skrifa's interpreter, which runs a program to its end and cannot stop after each instruction. M13.52 ports that interpreter into `crates/engine/src/ttvm` (credited in `NOTICE`) and adds a stepping API that exposes the stack, storage, graphics state and both zones. The port keeps the upstream behaviour, so the debugger's points equal the preview's: a test runs glyph programs to their end in both and compares the end points. If skrifa gains a stepping API, the debugger can use it and the copy can be dropped |
| URL scheme | `url.open` parses `fontcraft://show/?path=…&glyph=…&production=…&layer=…` as the reference's `show` path does; any other path is refused, so a web page cannot run commands. ### M13.20b Auto-spacing by shape classes (builder, wave 9)

Auto-spacing fits one area equation along a single line for the whole font (D11 in § 3), so sides
unlike the controls miss the stored values. The `classes` model gives each side the sidebearing of
the nearest control side (n, o, v; capitals and figures H, O, V; each also mirrored; plus glyphs
named in `references`), matched on the mean clipped depth of three zones, straightness and the
height of the extreme, plus the difference in white. A variant counts white with a soft depth limit
(`L·(1 − e^(−d/L))`); with no controls the side falls back to `model: "area"` and the result says
so. A harness in the style of X.tune1's `tune.rs` compares today's model, `classes`, `classes` with
soft depth, and that with zone weights fitted once on Oswald; the best worst-master median becomes
the default of method `optical`. No other sweeps.

Rows: `spacing.autoSpace` (guesses rewritten), `spacing.autoSpaceMethod` (notes).
Needs: nothing. M13.21c runs after it, since both read `profile.rs`.
Files: new `crates/spacing/src/space_model.rs` (pure); `crates/spacing/src/profile.rs` (zone means,
additive); `crates/engine/src/cmd/autospace.rs` (`model`, `references`, `classes` in the result);
`crates/engine/tests/engine/autospace.rs`; `corpus_autospace.rs` (also prints medians without the
control and reference glyphs); D11 in § 3 and the results in § 5.
Tests: on a synthetic font, b's left side takes n's, c's left takes o's, d's right takes n's, and
the controls keep their values; `model: "area"` gives today's values; `references` changes the
match; no controls, all sides empty, or 10,000 references fail with a message.
Measure: `cargo test --release -p fontcraft-engine --test engine corpus_autospace:: -- --ignored
--nocapture`; median at most 10% for lowercase and capitals in every master of Inter and Oswald, one
Inter master under 500 ms. If no candidate reaches it on Inter, commit the best one that beats
today's model, report the 20 worst sides per master with their class, and stop (open decision 2 in
`depth.md`).
Guesses: nearest-class matching and the soft depth are our own design.

### M13.21b Kerning audit and cross-master matching (writer, wave 9)

The kerning tools cannot find class pairs that collide at the glyph level, and masters can carry
different pair sets, which breaks variable kerning. The audit expands class pairs to glyph pairs
(capped by a named limit), measures each pair's closest approach with Kern to Distance's exact
distance, and reports pairs that collide or come closer than `threshold`; with `fix` it adds the
exceptions that restore the threshold in one undo step. Matching flattens class kerning, copies the
main master's groups to the others, gives every master the same pairs (zero where missing) and
compresses again.

Rows: `kerning.auditExceptions`, `kerning.matchAcrossMasters`.
Needs: nothing.
Files: new `crates/engine/src/cmd/kerning_audit.rs`; the distance helper in `cmd/autokern.rs`
becomes `pub(super)`, the only change there.
Tests: a synthetic A V pair at −200 that collides is found and fixed; a pair below the limit is not
reported; two masters with different pair sets end with the same set; hostile pair counts fail with
a message.
Measure: on Inter Roman, `matchAcrossMasters` changes no effective kerning value; the variable
export's `GPOS`, compared at each master with `fontcraft-cli oracle --variable`, equals the export
before the run.
Guesses: `fix` adds glyph–glyph exceptions, not group exceptions; matching adds zero pairs, then
compresses again.

### M13.72 Script modules: runtime (writer, wave 12; waits on open decision 7)

Scripts cannot read the font and decide: macros have fixed steps and modules see one layer. ABI
version 2 adds the module kind `script`. It takes parameters and a read-only font summary (names,
Unicode values, categories, masters, metrics, selection) plus any layers it asks for, and returns
command steps or a request for more layers, at most 16 rounds within a byte budget. The host checks
the steps and runs them as one transaction and one undo step. Scripts have no imports; ABI version
1 modules run unchanged.

Rows: `script.scope`, `script.requiresModules`, `extensions.sandboxCapabilities` (depth).
Needs: open decision 7 in `depth.md`.
Files: new `crates/plugins/src/script.rs`.
Tests: a script adds `.sc` glyphs for every lowercase letter in one undo step; hostile scripts (too
many rounds, oversized output, unknown commands) change nothing.
Measure (one builder run): a script over 1,000 glyphs under 1 s.
Guesses: the round limit and budgets; the shape of the font summary.

Rows: none; the protocol goes in `docs/mcp.md`.

### X.pdf3 Native clipboard flavours through crates (writer, wave 10)

The desktop app reads the clipboard's PDF by running `osascript` on macOS and PowerShell on Windows,
which costs a process per paste and moves the PDF as hexadecimal. On Windows clipboard-win and on
macOS objc2-app-kit, both already in `Cargo.lock`, read the PDF flavour directly. Linux keeps
`wl-paste` and `xclip` unless a crate carries custom MIME types. The 64 MiB cap and the read on a
worker thread stay.

Rows: `edit.paste` (notes).
Needs: X.pdf2.
Files: `apps/fontcraft/src/clipboard.rs`, `apps/fontcraft/Cargo.toml` (target-specific
dependencies).
Tests: the size cap and "no PDF" in each platform module, compiled on its own target; the existing
`ClipboardFlavours` paste tests unchanged.
