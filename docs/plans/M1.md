# M1 plan: source model and file I/O

_Planning pass of 2026-10-07. Status: **accepted by the owner 2026-10-07**; one agent throughout._

M1 grows the M0 model into the full source model and adds reading and writing for every source
format, plus opening compiled fonts. Everything after it (compiler oracles, real test fonts, the
editor) depends on M1.

## 1. Scope

### In

| Area | Rows | What "done" means |
|---|---|---|
| Model | `docs/spec/30-source-formats.md` › Recommended model | The full outline: axes, masters, instances, all layer kinds, shapes, kerning, features, ordered parameters, tagged `extra`, `Arc` tree |
| Native format | `fontcraft`, `roundtrip.native*` | Format version 2 with an in-memory upgrade from version 1; optional gzip |
| `.glyphs` | `glyphs2`, `glyphs3`, `glyphs4`, `glyphspackage`, `roundtrip.glyphs*` | Read and write all three versions and the package form; byte-identical no-op saves of app-written files |
| UFO and designspace | `ufo2`, `ufo3`, `ufoz` (read), `designspace4`, `designspace5`, `roundtrip.ufo*`, `roundtrip.designspace*` | A designspace and its UFOs open as one document and save back to the same files |
| Compiled fonts | `ttf.open`, `otf.open`, `ttc.open`, `woff.open` | Opened as a view-only one-master document; glyph order kept in `glyphOrder` |
| Save behaviour | `roundtrip.atomicSave`, `…unchangedFilesUntouched`, `…externalChangeDetected`, `…lossReport`, `…idsStable` | As the rows say |
| Commands | `file.open`, `file.save`, `file.saveAs`, `file.new`, `file.exportUfo`, `command.batch`, `font.inspect`, `font.listGlyphs`, `tables.list`, `font.dumpTables` | Registered, tested, reachable from CLI, control channel and MCP |
| CLI | `info`, `glyphs list`, `tables list`, `dump` | On the commands above |
| M0 debt | `docs/status.md` › Known limits, the eight rows marked M1 | Fixed |

| Item | To | Why |
|---|---|---|
| `woff2.open` | M2 (`container` crate) | Needs a WOFF2 decoder (Brotli plus the `glyf`/`loca` transforms). M2 builds the `container` crate for writing WOFF2 anyway |

| Renaming glyphs to the built-in naming scheme on open (`open.appliesNamingScheme`, `fontInfo.useCustomNaming.import`, `import.keepGlyphNames`) | M4 | Needs the `glyphdata` crate. M1 keeps the file's names, which matches the reference's "keep names" setting |

## 2. What the planning pass found

- **The corpus is fetched and the oracles are installed** on the build box: fontc 1.0.0 (cargo),
  fontmake 3.12.1 with glyphsLib and fontTools (uv). Corpus size 226 MB.
- **Corpus contents.** 232 `.glyphs` files (75 version 2, 157 version 3), 14 packages, 140 UFOs,
  1 UFOZ, 112 designspace files. 182 of the `.glyphs` files carry an `.appVersion`, meaning the
  reference app saved them at some point (fontc's test files may have been edited by hand since).
  At least 58 UFOs were written by fontTools ufoLib (paths with spaces were not counted).
- **There is no version 4 file in the corpus.** The owner has no licence, so we cannot make any.
  GlyphsSDK (Apache-2.0) publishes v2 and v3 samples and a v3 package, but no v4 sample. GitHub
  code search finds public v4 files (for example an Andika test fixture, a few OFL families and
  course material); each needs a licence check before it is pinned. Without v4 samples, the v4
  writer can be built from the schema but its byte fidelity cannot be measured.
- **GlyphsSDK's sample files belong in the corpus.** They exercise many documented keys on purpose.

### M1.0 Corpus, harness and spikes

1. Pin GlyphsSDK (Apache-2.0) in `xtask/corpus.toml`.
2. Find openly licensed version 4 files: check each candidate repository's licence, pin the ones
   that pass, and record the licence check in `corpus.toml`.
3. `cargo xtask roundtrip [--format glyphs|ufo|designspace|native] [--report]`: runs a reader and
   writer over the corpus and prints counts of byte-identical, semantically equal, different and
   failed files, with the first differing line per file. M1.1 to M1.4 plug into it. This command
   produces the progress numbers for the whole milestone.
4. Spike (question 10): read the `openstep-plist` and `glyphslib` source. Write the result into
   this plan.
5. Spike (questions 11 and 16): run norad over the corpus UFOs and designspace files. Write the
   numbers into this plan, then ask the owner.

### M1.1 Property lists (`crates/plist`)

- OpenStep (as the `.glyphs` format writes it) and XML property lists, reading and writing.
- A `Value` that remembers key order and number tokens (`1.0` stays `1.0`), whether a string was
  quoted, and the escapes it used.
- Writer options per dialect: `.glyphs` v2, v3, v4 (trailing commas, compact tuples) and
  ufoLib-style XML.
- Limits on input size, nesting depth and string length; truncation and corruption fuzz tests.
- **Gate measure:** generic round trip (parse, then write, no model) is byte-identical for every
  app-written `.glyphs` file and package in the corpus, and for every ufoLib-written `.plist`.

### M1.2 The model (serial: everything else depends on it)

1. Vocabulary: `Value` (from `plist`), tagged `Extra`, `Param`/`Params`, `Property`, `UserData`.
2. Document: `Arc` fields on `Font`; `GlyphTable` with a name index (fixes the linear scan).
3. Axes, metric definitions, masters, instances, with the model functions that keep parallel
   lists consistent (`roundtrip.glyphsDependentValues`).
4. Glyphs, layers with combinable attributes, backgrounds, shapes, nodes (32 bytes), components
   with decomposed transform and original matrix, anchors, guides, hints, annotations, images.
5. Kerning (three direction tables by master), UFO group facts, features as snippets.
6. `Font::check` and `check_changed` for the new invariants; limits for every new count.
7. Native format version 2: the model as JSON per `roundtrip.nativeDiffFriendly`, an upgrade
   from version 1, optional gzip by sniffing.
8. M0 debt: no undo step for an edit that changes nothing; reject `extra` keys that collide with
   known fields; parse once on load; `write_atomic` keeps symlinks and file mode; history list not
   copied per command; a command to switch the active document; refuse opening the same file twice.
9. Port `engine`, `compile` and `ui-egui` to the new model. All existing tests stay green.
10. Measure question 13 on Inter once M1.3 can read it.

### M1.3 `.glyphs` and packages (`crates/io-glyphs`)

- Read versions 2, 3 and 4 into the model; v2 spellings upgraded in memory, the original version
  kept for saving (`roundtrip.glyphsFormatVersionKept`).
- Write each version back from the model: defaults omitted, derived layer names not written,
  start-node rotation, `.appVersion` kept.
- Packages: `fontinfo.plist`, `order.plist`, `UIState.plist`, `glyphs/*.glyph`, and the v4 files
  (`kerning.plist`, `note.md`, `features/*.fea`); the reference's glyph-name-to-file-name rule;
  only changed files rewritten.
- **Gate measures:** byte-identical model round trip for every app-written file and package;
  `glyphs-reader` (fontc) and glyphsLib read our output and report the same glyphs, layers and
  node counts as for the original.

### M1.4 UFO and designspace (`crates/io-ufo`)

The design depends on the spike in M1.0 and the owner's answer on question 11. Either way:

- A designspace and its UFOs merge into one document; saving splits it back into the same files
  (`roundtrip.ufoMastersShareStructure`, `roundtrip.designspaceVerbatim`).
- GLIF file names, layer directory names, identifiers, libs and `data/` kept verbatim.
- UFO 2 read and (per question 12) written; UFOZ read.
- Glyphs-only data carried in lib keys spelled as glyphsLib spells them (question 7).
- **Gate measures:** byte-identical round trip of the ufoLib-written UFOs and of the designspace
  files; norad reads our output; a `.glyphs` → UFO → `.glyphs` trip loses only what the loss
  report lists.

### M1.5 Opening compiled fonts (`crates/decompile`)

- TrueType and CFF outlines through `read-fonts`/`skrifa`: quadratic curves stay quadratic,
  components stay components; names, metrics, `cmap`, vertical metrics, alignment zones and stems
  (CFF) into the model.
- Collections (each member as its own document) and WOFF 1 (zlib).
- `glyphOrder` parameter recorded; the document is view-only until saved to a source format.
- **Gate measures:** every compiled font in the corpus opens without error; glyph count, code
  points and outlines match `skrifa`'s own reading.

### M1.6 Commands and CLI

- `file.open` detects the format from content, not from the file name; `file.save` and
  `file.saveAs` take a format and version and return the loss report; external changes are
  detected before overwriting; `file.exportUfo`; `command.batch` as one undo step.
- Queries: `font.inspect`, `font.listGlyphs`, `tables.list`, `font.dumpTables` (JSON and readable
  text).
- CLI: `info`, `glyphs list`, `tables list`, `dump`; `convert` gains every source format.
- Command sweep and hostile-input tests extended to every new reader and command.

## 6. Risks

| Risk | Effect | Mitigation |
|---|---|---|
| No v4 sample files with a usable licence | v4 byte fidelity cannot be measured | v4 written from the schema and marked unmeasured in ROADMAP; recheck GitHub each milestone |
| fontc's test files were edited by hand after the app saved them | Byte identity fails for reasons that are not our bug | The harness reports per file; files shown to be hand-edited go on an allow-list with the reason |
| The model port breaks M0 behaviour | The gate goes red for a long stretch | Port in steps, each commit green; old tests kept until replaced |
| Inter's size exposes performance limits | Opening is slow, undo memory grows | Measure early (question 13); architecture targets: open in under 500 ms |
