# M1 plan: source model and file I/O

_Planning pass of 2026-10-07. Status: **accepted by the owner 2026-10-07**; one agent throughout._

M1 grows the M0 model into the full source model and adds reading and writing for every source
format, plus opening compiled fonts. Everything after it (compiler oracles, real test fonts, the
editor) depends on M1.

## 2. What the planning pass found

- **The corpus is fetched and the oracles are installed** on the build box: fontc 1.0.0 (cargo),
  fontmake 3.12.1 with glyphsLib and fontTools (uv). Corpus size 226 MB.
- **Corpus contents.** 232 `.glyphs` files (75 version 2, 157 version 3), 14 packages, 140 UFOs,
  1 UFOZ, 112 designspace files. 182 of the `.glyphs` files carry an `.appVersion`, meaning the
  reference app saved them at some point (fontc's test files may have been edited by hand since).
  At least 58 UFOs were written by fontTools ufoLib (paths with spaces were not counted).
- **There is no version 4 file in the corpus.** The owner has no licence, so we cannot make any.
  GlyphsSDK (Apache-2.0) publishes v2 and v3 samples and a v3 package, but no v4 sample. GitHub
  code search finds public v4 files (for example an Andika test fixture, a few OFL families and
  course material); each needs a licence check before it is pinned. Without v4 samples, the v4
  writer can be built from the schema but its byte fidelity cannot be measured.
- **GlyphsSDK's sample files belong in the corpus.** They exercise many documented keys on purpose.

### M1.0 Corpus, harness and spikes

1. Pin GlyphsSDK (Apache-2.0) in `xtask/corpus.toml`.
2. Find openly licensed version 4 files: check each candidate repository's licence, pin the ones
   that pass, and record the licence check in `corpus.toml`.
3. `cargo xtask roundtrip [--format glyphs|ufo|designspace|native] [--report]`: runs a reader and
   writer over the corpus and prints counts of byte-identical, semantically equal, different and
   failed files, with the first differing line per file. M1.1 to M1.4 plug into it. This command
   produces the progress numbers for the whole milestone.
4. Spike (question 10): read the `openstep-plist` and `glyphslib` source. Write the result into
   this plan.
5. Spike (questions 11 and 16): run norad over the corpus UFOs and designspace files. Write the
   numbers into this plan, then ask the owner.

### M1.1 Property lists (`crates/plist`)

- OpenStep (as the `.glyphs` format writes it) and XML property lists, reading and writing.
- A `Value` that remembers key order and number tokens (`1.0` stays `1.0`), whether a string was
  quoted, and the escapes it used.
- Writer options per dialect: `.glyphs` v2, v3, v4 (trailing commas, compact tuples) and
  ufoLib-style XML.
- Limits on input size, nesting depth and string length; truncation and corruption fuzz tests.
- **Gate measure:** generic round trip (parse, then write, no model) is byte-identical for every
  app-written `.glyphs` file and package in the corpus, and for every ufoLib-written `.plist`.

**Progress (2026-10-07): OpenStep done.** The XML part waits for the answer on question 11.

| Measure | Result |
|---|---|
| `.glyphs` sources identical, all | 215 of 274 (single files 187 of 245, packages 28 of 29) |
| Reference-written sources outside fontc's test data | 35 of 35, guarded by `crates/plist/tests/corpus.rs` |
| Version 4 | 16 of 16 |
| Failed to read, or read back to different values | 0 |
| Spellings kept (tokens the canonical rules would write differently) | 176, mostly fontc hand edits |

Rules found on the way, for the `.glyphs` writer (M1.3):

- The trailing comma after the last element of a multi-line list is a version 4 rule; no
  unedited version 2 or 3 file has one.
- Every string containing `-` or `/` is quoted (10,711 cases, no exception). A bare string needs
  at least one letter or digit (`..` is quoted, `.notdef` is not).
- Version 2 writes code points as bare hexadecimal with leading zeros (`unicode = 0041;`); the
  property-list layer reads them as strings, and the `.glyphs` reader must interpret them.
- Number-like dictionary keys are bare in `Axis Mappings` and quoted in string-keyed settings
  (TrueType `deltaV`). The model writer needs a per-key choice, so `Str` needs a public way to ask
  for a bare spelling.

### M1.2 The model (serial: everything else depends on it)

**Progress (2026-10-07):** steps 1 and 2 done for the M0 fields: tagged `Extra` with property-list
values, `Arc` parts, the glyph table with its name index, metric definitions with per-master
values, layers with their own ids, transforms kept as written. Native format version 2 with an
upgrade from version 1. M0 debt fixed: name lookup, the top-level copy, the double parse, no-op
undo steps.

**`crates/io-glyphs`, first cut:** versions 3 and 4, single files. Typed: family name (v4 from
its `familyNames` property), units per em, version, metric definitions and values, masters, glyphs
(name, code points, export), layers (id, master, width), paths, nodes, components, anchors;
everything else in `Extra`. Shapes the model cannot hold are kept as raw shapes.

| Measure (model mode) | Result |
|---|---|
| Reference-written files, versions 2 to 4 | 17 of 17 identical, guarded by `crates/io-glyphs/tests/corpus.rs` (the format document's hand-arranged v2 sample is on the allow-list) |
| fontc's test data, versions 2 and 3 | 91 of 227 identical; 4 version 2 files fail to read, the rest differ by hand edits |

Version 2 (`crates/io-glyphs/src/v2.rs`): master metrics are fixed keys with a separate list of
alignment zones, which the reader turns into metric definitions with overshoots and the writer
rebuilds in descending order; hexadecimal code points; separate path and component lists; node,
transform and position strings. Glyphs, layers and masters have fixed key orders, taken from
glyphsLib's format 2 writer (Apache-2.0, credited in `NOTICE`); other objects sort byte-wise.

**Packages** (`crates/io-glyphs/src/package.rs`): `fontinfo.plist`, `order.plist` and one file per
glyph, assembled into the same root dictionary as a single file; other files (`UIState.plist`,
version 4 `features/*.fea`, `kerning.plist`, `note.md`) are kept in `Font::files` and written back
unchanged. Glyph file names follow the reference's rule (6,528 of 6,539 corpus files; the rest are
`.notdef` and `.null`, whose leading `.` becomes `_`, now part of the rule).

| Measure (model mode) | Result |
|---|---|
| Reference-written packages, versions 3 and 4 | 17 of 17 identical (Inter Roman and Italic among them) |
| fontc's hand-made packages | 5 of 12 identical |
| Inter Roman read / write (release build) | 205 ms / 146 ms; the architecture's target for opening is 500 ms |

A package's side files hold model data in format version 4: feature code (`features/*.fea`),
kerning (`kerning.plist`) and the note (`note.md`); in every version the display strings
(`UIState.plist`). The reader moves them into the root dictionary and the writer back out, so the
glyphspack fixtures' single file and package of the same font read into the same model (corpus
test), and either form saves as the other. Any other file in a package is kept and reported as a
loss when saving to a single file.

fontc's test data is hand-made: blank lines, unsorted keys, quoted plain names, missing required
keys, `over = 0`, empty `nodes = ();`; none of these occurs in a file the app saved. The harness
now counts it as hand-written.

1. Vocabulary: `Value` (from `plist`), tagged `Extra`, `Param`/`Params`, `Property`, `UserData`.
2. Document: `Arc` fields on `Font`; `GlyphTable` with a name index (fixes the linear scan).
3. Axes, metric definitions, masters, instances, with the model functions that keep parallel
   lists consistent (`roundtrip.glyphsDependentValues`).
4. Glyphs, layers with combinable attributes, backgrounds, shapes, nodes (32 bytes), components
   with decomposed transform and original matrix, anchors, guides, hints, annotations, images.
5. Kerning (three direction tables by master), UFO group facts, features as snippets.
6. `Font::check` and `check_changed` for the new invariants; limits for every new count.
7. Native format version 2: the model as JSON per `roundtrip.nativeDiffFriendly`, an upgrade
   from version 1, optional gzip by sniffing.
8. M0 debt: no undo step for an edit that changes nothing; reject `extra` keys that collide with
   known fields; parse once on load; `write_atomic` keeps symlinks and file mode; history list not
   copied per command; a command to switch the active document; refuse opening the same file twice.
9. Port `engine`, `compile` and `ui-egui` to the new model. All existing tests stay green.
10. Measure question 13 on Inter once M1.3 can read it.

### M1.3 `.glyphs` and packages (`crates/io-glyphs`)

- Read versions 2, 3 and 4 into the model; v2 spellings upgraded in memory, the original version
  kept for saving (`roundtrip.glyphsFormatVersionKept`).
- Write each version back from the model: defaults omitted, derived layer names not written,
  start-node rotation, `.appVersion` kept.
- Packages: `fontinfo.plist`, `order.plist`, `UIState.plist`, `glyphs/*.glyph`, and the v4 files
  (`kerning.plist`, `note.md`, `features/*.fea`); the reference's glyph-name-to-file-name rule;
  only changed files rewritten.
- **Gate measures:** byte-identical model round trip for every app-written file and package;
  `glyphs-reader` (fontc) and glyphsLib read our output and report the same glyphs, layers and
  node counts as for the original.

### M1.4 UFO and designspace (`crates/io-ufo`)

The design depends on the spike in M1.0 and the owner's answer on question 11. Either way:

- A designspace and its UFOs merge into one document; saving splits it back into the same files
  (`roundtrip.ufoMastersShareStructure`, `roundtrip.designspaceVerbatim`).
- GLIF file names, layer directory names, identifiers, libs and `data/` kept verbatim.
- UFO 2 read and (per question 12) written; UFOZ read.
- Glyphs-only data carried in lib keys spelled as glyphsLib spells them (question 7).
- **Gate measures:** byte-identical round trip of the ufoLib-written UFOs and of the designspace
  files; norad reads our output; a `.glyphs` → UFO → `.glyphs` trip loses only what the loss
  report lists.

### M1.5 Opening compiled fonts (`crates/decompile`)

- TrueType and CFF outlines through `read-fonts`/`skrifa`: quadratic curves stay quadratic,
  components stay components; names, metrics, `cmap`, vertical metrics, alignment zones and stems
  (CFF) into the model.
- Collections (each member as its own document) and WOFF 1 (zlib).
- `glyphOrder` parameter recorded; the document is view-only until saved to a source format.
- **Gate measures:** every compiled font in the corpus opens without error; glyph count, code
  points and outlines match `skrifa`'s own reading.

### M1.6 Commands and CLI

**Progress (2026-10-08), `.glyphs` part done:** `crates/engine/src/io.rs` recognises sources by
content and reads folders with limits; `file.open` opens `.fontcraft`, `.glyphs` and
`.glyphspackage`; `file.save` and `file.saveAs` (with `format` and `version`) keep the source's

return a loss report. `write_atomic` follows symlinks and keeps permissions. The CLI's `convert`
writes every source format. Converting between `.glyphs` versions is refused for now.

- `file.open` detects the format from content, not from the file name; `file.save` and
  `file.saveAs` take a format and version and return the loss report; external changes are
  detected before overwriting; `file.exportUfo`; `command.batch` as one undo step.
- Queries: `font.inspect`, `font.listGlyphs`, `tables.list`, `font.dumpTables` (JSON and readable
  text).
- CLI: `info`, `glyphs list`, `tables list`, `dump`; `convert` gains every source format.
- Command sweep and hostile-input tests extended to every new reader and command.

**M1.2 and M1.3 run together** (decided 2026-10-07, after M1.1). Every key the model has no field
for is kept in that struct's `Extra` as a property-list value with its spelling, so a `.glyphs`

in `Extra`. Each field the model then takes over is checked against the whole corpus at once.
This works because the reference writer sorts dictionary keys byte-wise: 155,488 of 155,527
dictionaries in reference-written files are sorted, and the exceptions are dictionaries ordered
by data (keyed by master id, kerning pairs) and a hand-written documentation sample.

## 8. Spike results (M1.0)

Run on 2026-10-07 against the corpus as pinned that day. The spike programs were throwaway code
outside the repository; the harness `cargo xtask roundtrip` takes over from here.

### 8.1 `openstep-plist` 1.1.0 and `glyphslib` 0.2.8 on `.glyphs` files

Each file was parsed and written back, then compared with the original byte for byte.

| Tool | Files | Identical | Different | Failed to read |
|---|---:|---:|---:|---:|
| `openstep-plist` (generic value, no model) | 245 | 0 | 245 | 0 |
| `glyphslib` (typed model) | 245 | 0 | 218 | 27, including all 5 version 4 files |

- The value type cannot keep spellings: dictionaries are `BTreeMap`s (sorted, so source order is
  lost where it is not alphabetical), numbers are `i64` or `f64` (so `1.0` and `1` collapse), and
  strings do not record whether they were quoted.
- The writer has one layout. The first difference in most files is an array the app writes over
  several lines and the crate writes on one, or the trailing comma version 4 puts after the last
  element of a multi-line list.
- The parser indexes and unwraps freely, so hostile input can panic it; our rules would require
  a guard around every call.

**Decision:** our own `plist` crate (M1.1). `glyphslib` and fontc's `glyphs-reader` stay as second
readers in tests (versions 2 and 3).

### 8.2 norad 0.19.0 on UFO and designspace

Each UFO was loaded and saved with the options closest to ufoLib (two-space indent, single quotes
in the XML declaration); each designspace file was loaded and saved.

| Source | Count | Identical | Different | Failed to load | Files identical |
|---|---:|---:|---:|---:|---:|
| UFOs written by ufoLib | 61 | 0 | 59 | 2 | 45 of 632 |
| Other UFOs (older tools, test fixtures) | 79 | 0 | 64 | 15 | 34 of 15,550 |
| Designspace files | 112 | 0 | 111 | 1 | – |

- **Layout norad does not follow:** ufoLib indents the root element of a property list; GLIF
  attributes are written in another order (`height` before `width`) and elements in another order
  (`unicode` before `advance`). Indentation and quote style are norad's only layout options.
- **Designspace:** attributes are reordered (`name` before `tag`), a `default` attribute is added,
  the encoding's case changes, comments are dropped.
- **Load failures:** a missing `metainfo.plist` or `layercontents.plist`, a `lib.plist` it rejects,
  GLIF files its strict parser rejects, and a designspace with two `mappings` elements. Some of
  these are deliberately broken fixtures, where failing is right; the rest are real files.

**Recommendation:** our own UFO and designspace reader and writer, on the `plist` crate and an XML
tokenizer, written to ufoLib's layout; norad kept as a second reader in tests. This changes
decision 0003 and waits for the owner.
