# M10 plan: hinting (PostScript and TrueType)

_Planning pass of 2026-10-11. Status: **accepted**: the orchestrator answered § 7 on the owner's behalf; the answers are in § 7 and in the rows._

M10 adds both kinds of hinting. On the PostScript side: the font-level hints (alignment zones,
standard stems and the optional Private dict numbers) are validated and written in full, manual
stem and ghost hints are edited in Edit View and written to the CFF charstrings with hint
replacement and flex, and an autohinter ported from AFDKO's `otfautohint` hints every other glyph
at export. On the TrueType side: TT zones and TT stems per master, the TrueType Instructor tool with
its five instruction types, a compiler from those instructions to `glyf` bytecode with our own
`fpgm`, `prep` and `cvt `, the `gasp` table, a grid-fitted preview (Edit View outlines, pixel
backdrop, waterfall, web page), a TrueType autohinter, and the import and write-back of hinting from
opened binary fonts. The plan is cut into 33 packages so that most of them can be written in
parallel worktrees once the interface skeleton M10.1 is in.

## 3. Answers and decisions

### Design decisions

| Question | Answer for M10 |
|---|---|
| Where the code lives | Three new crates. `hinting` (L2: `model`, `geom`, `glyphquery`): typed views of PostScript hints and TrueType instructions over the stored hint values, node references and their upkeep, the hint settings of a master or instance with defaults and scopes, the font-hint checks, the TrueType execution model (order, touched points), the compiler from instructions to bytecode with our `fpgm`, `prep` and `cvt `, and the TrueType autohinter. `autohint` (L1: `geom`): the PostScript autohinter, ported from otfautohint, pure functions from contours and a zone-and-stem set to hints. `ttasm` (L0 alone): TrueType bytecode assembler, disassembler and stack analysis. `cff` gains the hint operators, `compile` the point map and the hinting stages, `decompile` the import, `render` the hinted rasterizer (skrifa) |
| How hints are stored | As today: the stored hint values on the layer (`LayerInfo.hints`), so `.glyphs` files round-trip unchanged. `hinting` parses them into typed hints and writes edits back in the same keys. TT zones and TT stems stay in the TTFZones and TTFStems parameters, read through typed views. No new model field |
| Node references | The source's (path index, node index) pairs. After every font-changing command that changes the node structure of a layer with hints (insert, delete, reverse, start point, Remove Overlap, Expand Outline…), the engine remaps the references of that layer in the same undo step: nodes are matched old to new by path, position and type; a PostScript end whose node is gone becomes a number at the node's last position; a TrueType instruction whose node is gone is removed and the command reports it. This also closes the known gap in `docs/status.md` that some path commands do not renumber hints that refer to a path by index |
| Main master and fallbacks | Get Hints From Master names it, else the first master. PostScript: a glyph without hints there takes them from the first other master that has some; special layers that replace the main master's layer carry their own. TrueType: only the main master's instructions count |
| PostScript export | Per glyph: manual hints when the hint-source layer has any, resolved through node links in the master being built; else the autohinter, unless Autohint is off, the glyph is in Disable autohinting for glyphs, or Export PostScript Hints is off. Widths made positive, ghost hints written with the reserved widths (−20 top, −21 bottom), overlapping hints split into masks by the autohinter's substitution step, flex wherever the flex test passes |
| PostScript autohinter | A faithful port of otfautohint (Apache-2.0, credited in each file and in `NOTICE`), its defaults kept, measured glyph by glyph against otfautohint itself (§ 5). The reference's autohinter is not documented (question 12 of the PostScript note) |
| TrueType manual export | Autohint off: each main-master layer's instructions compile to a glyph program against the exported point numbers; glyphs without instructions get none; `cvt `, `fpgm`, `prep` are written when any glyph has instructions or the masters carry imported tables. Autohint on: the autohinter replaces every manual instruction (§ 7, question 2) |
| Point numbers | The outline stage keeps a map from each source node to its exported point: on-curve nodes keep their identity through the cubic-to-quadratic conversion; an off-curve node maps to the nearest off-curve point of its segment; Remove Overlap maps a removed node to the nearest point the removal creates (the handbook's rule); components resolve through their base glyph's map |
| Our TrueType programs | `fpgm` functions for zone rounding (with the rounding threshold and the doubled threshold for `xHeight`), stem widths per rendering intent, the five rounding modes (the GDI-only mode through GETINFO), triple hints, the minimum distance and diagonal preservation; `cvt ` laid out as zones then stems; `prep` with zone alignment, per-PPM zone and stem deltas, overshoot suppression and the instruction-control setup. Written from the TrueType instruction set specification; nothing is taken from the reference's output |
| Preview engine | skrifa runs the compiled programs (TrueType interpreter) and the CFF hints (PostScript hinter) on a font compiled in memory; tiny-skia (already used by `render`) draws the pixel backdrop. The handbook says the reference draws with Microsoft's code; skrifa follows FreeType (§ 7, question 4) |
| `gasp` | From the gasp Table parameter (instance, then font) or a UFO's range records; a TrueType font with instructions and no such source gets the handbook's default thresholds 8 and 20 with DOGRAY + SYMMETRIC_SMOOTHING up to 8 PPM, GRIDFIT + SYMMETRIC_GRIDFIT up to 20 and all four bits above (guess); an unhinted font without a source gets no `gasp`, as fontc and fontmake do |
| Imported hinting | Opening a hinted TrueType font stores `cvt ` as the CVT Table parameter and `prep` and `fpgm` as assembly text in the prep and fpgm Table Assembly parameters on every master; glyph programs go to layer user data with an outline fingerprint and are written back while the outline is unchanged. Opening a CFF font turns its stems into numeric layer hints and its Private dict into zones, stems and blue parameters |
| Commands and targets | Commands take explicit targets: a glyph, a layer (master id), hint or instruction indexes, node references as `[path, node]`. View state (pixel size, direction, intent, preview scale, point indexes, pixel preview) lives in UI commands, as `UI_COMMANDS` requires |
| Undo | Every font-changing command is one undo step, the reference upkeep included; a refused command leaves the font pointer-equal |

### Limits (never crash)

| What | Limit |
|---|---|
| Hints and instructions on one layer | the existing `MAX_LAYER_HINTS` (4,096) |
| Node reference | path and node indexes checked against the layer; a dangling reference is an error message, never an index panic |
| Alignment zones per master read for export | 7 BlueValues pairs and 5 OtherBlues pairs written (the CFF limits), the rest reported; at most 64 zones accepted in a source |
| Stems per master | 12 per direction written to StemSnap; at most 64 stem definitions in a source |
| TT zones, TT stems per master | 256 each (the `cvt ` budget below) |
| `cvt ` entries | 4,096 |
| Delta cells | PPM 1 to 255 (the reach of DELTAP with a delta base), at most 64 columns × 255 rows per table |
| Pixel size in the Instructor | 4 to 400 PPM |
| Autohinter input | 100 segments per direction (otfautohint's `--max-segments` default: a direction with more is skipped and reported), 65,535 points per glyph, coordinates finite and within ±`MAX_COORDINATE`; work per glyph bounded by the segment cap |
| Override sets (fontinfo) | 1 MB of text, 256 sets, 64 counter-glyph names per list (otfautohint's extension limit) |
| Control instructions | 1 MB of text, 100,000 lines |
| Assembly text (prep, fpgm, glyph programs) | 1 MB per program; IF and FDEF nesting 64 deep; assembled glyph programs at most 65,535 bytes (the `glyf` field) |
| Interpreter runs | skrifa's own bounds (call depth, loop guard) plus our cap on instructions executed per glyph, checked in M10.1 against skrifa's source; a program that exceeds it renders unhinted with a message |
| Web preview server | one page and one font, 4 connections at a time, 64 KB of request headers |
| Names (zones, stems) | `MAX_NAME_LEN` |

"builder" packages run in the main checkout, one at a time; "worktree" packages run in parallel
without builds or tests, each with one compile check before it commits. Every module a worktree
package fills is created and registered by M10.1, so no worktree package edits `cmd/mod.rs`,
`xtask/src/layers.rs`, a `Cargo.toml` or a shared module list. Each package edits only its own
rows' `notes` and `guesses` when behaviour turns out different, and names the change in its report.

**Can the TrueType hinting IDE be cut into small packages?** Yes, along the seams above: the
instruction data and execution model (M10.2, M10.6), the commands in two halves (M10.6, M10.7), the
assembler (M10.16), the font programs (M10.17) and glyph programs (M10.18), the export (M10.19), the

Delta table, zone and stem editors, waterfall) plus the web preview. Only M10.19 and M10.21 need a
builder: the point map touches the shared outline stage, and the autohinter is tuned against
measures. The rest can be written blind in worktrees once M10.1 has fixed the types they share

### M10.21c TrueType autohinter misses and a wider measure (builder, wave 11)

M10.21b reported x-height rows at 92.9% (target 95%) and zone agreement at 98.29% (target 99%), but
the measure covers only 7 of 325 sources: three distinct fonts (Oswald, COLRv1-gradient, and
IntermediateLayer counted five times), and no Inter. 253 sources are skipped as having no Latin
and 65 fail inside the script. The 11 x-height misses all come from one fault: in COLRv1-gradient
the 16 x-height extremes stay at their unhinted position at every size while the cap-height ones
snap. The 99% zone target is ours: ttfautohint itself puts only 91.6% of Oswald's extremes on the
row.

First the script: fonts without `H`, `x` or `o` are skipped with a reason; a font built from
several source formats counts once (hash of the unhinted `glyf`); Inter (static Regular), the
Glyphs SDK samples, openplotfont, markow and the glyphspack sources with Latin join the set. The
new baseline is recorded before any code change. Then the COLRv1 fault is fixed
(`drop_unmeasured_zones` and the x-height scaling in `autohint_prep` first), and the
IntermediateLayer and Oswald misses are classified.

Rows: `autohint.tt.run`, `export.autohintTrueType`, `autohint.tt.option.increaseXHeight`,
`hinting.tt.export.autohintIgnoresManual`.
Needs: none.
Files: `crates/hinting/src/tt_auto.rs`, `tt_testfont.rs`; the M10.21b measure script.
Tests: a font in `tt_testfont.rs` that reproduces the COLRv1 case, run in skrifa.
Measure: on the widened, deduplicated set, x rows ≥ 95% and zone extremes ≥ 99%, with font size
not above ttfautohint's.

### M10.33 PostScript autohinter against otfautohint (builder, wave 10)

§ 5 sets "≥ 99.5% of glyphs identical to otfautohint on every static CFF corpus build", but that

also times Inter Regular as CFF. Overlap-union input points, which otfautohint keeps, are
classified, not chased.
