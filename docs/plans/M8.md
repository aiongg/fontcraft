# M8 plan: OpenType features

_Planning pass of 2026-10-11. Status: **accepted**, with the answers in § 7 decided by the orchestrator on the owner's behalf._

M8 makes feature code work. Exported fonts get `GSUB`, `GPOS` and `GDEF` compiled from the
font's prefixes, classes and features, with the generated kerning and mark attachment inserted
where the code asks for them. The reference's additions to the feature language (tokens,
`delete`, `standalone` and the other extensions) are expanded before compiling. Update writes
the automatic prefixes, classes and features from the glyph names. The Features tab of Font Info
edits all of it, with errors mapped back to the entry and line that caused them. Edit View
previews substitution features through a shaper, Text Preview shapes its text as an application
would, and feature files can be imported, exported and rebuilt from compiled fonts.

Two choices carry the milestone. The feature compiler is fontc's `fea-rs`, as decision 0002
already says, wrapped in a crate that keeps its older `write-fonts` version and its panics away
from the rest of FontCraft. The shaper is `harfrust`, the HarfBuzz project's Rust port, which
reads fonts through the `read-fonts` version the workspace already uses.

## 3. Answers and decisions

### Design decisions

| Question | Answer for M8 |
|---|---|
| The feature compiler | fea-rs 1.0.0 from crates.io (decision 0002, item 4), in a new standalone crate `fea` that depends on no FontCraft crate. It is the only crate that sees `write-fonts` 0.52 (a renamed dependency); it hands tables out as bytes, which `compile` adds with `FontBuilder::add_raw`, and takes generated lookups in neutral types of its own (§ 7, question 2). When fea-rs releases on `write-fonts` 0.54, the rename goes and nothing outside `fea` changes. The other font crates line up: fea-rs needs no `read-fonts` or `skrifa` of its own beyond what `write-fonts` 0.52 pulls in (`read-fonts` 0.43, inside `fea` only), and harfrust 0.14 requires `read-fonts` 0.45, the workspace's; `skrifa` 0.48 is used by nothing M8 adds. No released fea-rs matches 0.54 (0.22 and older are on earlier versions still), and bumping the workspace back to 0.52 would undo M2's table builders' version |
| Calling fea-rs safely | Every call runs after our pre-checks and under the engine guard, on a thread with a 64 MB stack on native targets. The pre-checks: text size, a closed set of virtual files served by our resolver (paths normalised inside the source folder, file count capped), brace and bracket depth, and a walk over the parsed tree that adds up class sizes with saturating counts and caps the product of ligature and contextual class sizes, ligature length and the total rule count, before `validate` and `compile` run. On wasm, where a panic aborts, the same checks run with lower caps (§ Limits) |
| Assembly and error positions | Each prefix, class and feature becomes one virtual file holding its full statement (`@Name = [ … ];`, `feature tag { … } tag;`), and a root file includes them in the oracles' order: classes, prefixes, features, each group in sidebar order (`featureEditor.outputOrder`). Lowering and token expansion keep an offset map per entry, so a fea-rs diagnostic (file id, byte span) maps to the entry and the range in its stored code |
| Tokens and extensions | Expanded by FontCraft before fea-rs sees the text (fea-rs has number values only and a partial predicate subset): number values, glyph properties and predicates are evaluated per target through a `TargetValues` interface, which M8 implements for masters and M9 for instances and the variable font; the extensions are lowered to standard syntax (`docs/spec/12-feature-code.md` § 4, with `standalone` lowered by splitting the feature block) |
| The predicate language | One parser and evaluator in `glyphquery` (`predicate.rs`), used by predicate tokens and by the smart filter's Custom rule: the comparators of Apple's documented predicate format, which glyphsLib also follows, keywords in any case, NOT before AND before OR, parentheses, `class(Name)`. The attributes of the handbook's table plus the common glyph properties; any other is an error naming it |
| Implicit features | The generated `kern`, `dist` (M5.17) and `mark`, `mkmk`, `abvm`, `blwm`, `curs` (M6.17) are handed to fea-rs's `FeatureProvider` as neutral lookups and converted to its builders inside `fea`, so they land at `# Automatic Code` or are appended or skipped by ufo2ft's rules, as in fontc. The M5 block scan and its warnings go. Kerning scripts then include the language systems of the code and the scripts its substitutions reach, as fontc computes them (the closure M5.17 left out) |
| Variable fonts (M9's interface) | `fea` takes an optional `FeaVariations` interface of our own (axes with tags and ranges, the masters' normalised locations, number values per location, and turning per-location values into a default plus deltas), adapted inside `fea` to fea-rs's `VariationInfo`; M8 passes none for static builds and M9.12 implements it. Feature text with `conditionset` and `variation` blocks passes through assembly and lowering unchanged, because fea-rs parses them; M9.11's preprocessor for the reference's `condition` and `(axis:coord)` forms plugs in as `features::variable::lower`, run after token expansion for `Target::Variable`. The neutral generated lookups carry values as a default plus optional deltas over normalised regions (M9.9 fills the deltas for kerning and marks) and a list of feature variations (condition sets with single substitutions and the feature tag), which `fea` hands to fea-rs's `add_feature_variations`, so M9.8's bracket-layer substitutions merge into the compiled `GSUB` |
| `GDEF` | From the code's `GDEF` block when it has one, else M6.17's classes and carets, as fontc does |
| Automatic features | Our own code, written from the handbook's table and from the reference's stored output in the corpus taken as a black box (§ 2). Neither oracle generates automatic features, and no permissive implementation exists. Update writes the code into the entries (automatic flag on); export regenerates the automatic entries for each target's glyph set unless Update Features is off, as the handbook says automatic code adapts to each instance (§ 7, question 4) |
| The preview font | `compile` builds a layout-only font for one master on Compile: `head`, `maxp`, `cmap`, `hhea`, `hmtx`, `GDEF`, `GSUB`, `GPOS`, `post`, with every unencoded glyph mapped to a plane 15 or 16 private-use code point in a lookup table kept beside it (not in `cmap`). The engine keeps the last compile per document (bytes, feature list, diagnostics, font revision); it is session state, not undoable, and never saved. The Features menu lists its features (`features.menuNeedsCompile`) |
| The shaper | harfrust 0.14 (`std` only, never its `icu` feature, which pins another `icu_properties`), in a new L2 crate `shaping` with unicode-bidi (UAX #9, through `icu_properties`' `unicode_bidi` data) and our own script itemisation from `icu_properties` Script_Extensions. Plans are cached per (preview font, direction, script, language, feature list); glyphs typed by name reach the shaper as their private-use code points through `FontFuncs`, and advances come live from the model the same way, so outline and width edits need no recompile (§ 7, question 3) |
| Edit View shaping | harfrust applies `GSUB` for the features active in the tab, with Localized Forms setting the OpenType script and language tags; every `GPOS` feature is off. `textlayout` then applies kerning by the tab's kerning mode from the live kerning index and cursive attachment from the live `exit` and `entry` anchors, so kerning and anchor edits show at once and feature edits after Compile (`text.shaping`, `features.previewScope`). Each line keeps one direction, as in M5 |
| Text Preview shaping | harfrust with the script's default features and all of `GPOS` (generated kerning and marks included), on a full layout build of the previewed master that is rebuilt in the background once editing pauses for half a second; mixed directions ordered by UAX #9 (`textPreview.shaping`, `textPreview.unicodeBidi`). Only the lines in view are shaped |
| Contextual anchors | `anchor.setContext` writes the anchor's `GPOS_Context` user data; M8.21 extends M6.17's mark writer with contextual lookups as ufo2ft builds them; fontmake is the oracle (fontc does not support them) |
| Reconstruction from compiled fonts | A decompiler in `decompile` (`fea.rs`) turns `GSUB` and `GPOS` lookups into feature code: lookups used by several features go into a prefix named "Prefix" (handbook), pair kerning becomes kerning and groups as M5 reads it, contextual kerning stays feature code |
| Variable feature syntax (open decision D5) | FontCraft lowers the reference's variable syntax to the form fea-rs accepts (feaLib's: optional units, no `locationDef`), writes that form in exported `.fea` files and reads AFDKO's where fea-rs does. The work is M9's |
| Where the code lives | `fea` (new, standalone): the fea-rs wrapper. `features` (L2): assembly, source maps, lowering, tokens, automatic generators, the feature-tag registry, editor helpers (highlighting tokens, completion), snippets. `glyphquery`: predicates. `shaping` (new, L2): harfrust and bidi; `textlayout` uses it (a new intra-layer order `shaping` → `textlayout`). `compile`: the layout stage and the preview font. `engine`: commands and the per-document compile state. `ui-egui`: the Features tab, the Features menu, the Anchor Context field |
| Undo | Every font-changing M8 command is one undo step; Update is one step for all entries it writes; Compile changes no font data. A refused command leaves the font pointer-equal |

### Limits (never crash)

| What | Limit |
|---|---|
| Code of one entry | 4 MB; entries per font: the existing `MAX_SNIPPETS` (100,000) |
| Assembled text of one target, includes counted | 16 MB (4 MB on wasm) |
| Included files | 4,096 per compile, 50 levels (the specification's), paths inside the source's folder after normalising; a file read once |
| Brace and bracket depth | the existing `MAX_DEPTH` of the feature splitter (64) |
| Glyph class members | per class `MAX_GLYPHS` after de-duplication; all class expansions together 4,000,000 (500,000 on wasm), counted with saturation before fea-rs expands them |
| Ligature rule | 64 components; the sequences one rule expands to 100,000 |
| Rules after expansion | 2,000,000 (200,000 on wasm), as `MAX_KERN_RULES` |
| Tokens | 100,000 per entry; one expression 4,096 characters; predicate nesting 64; numbers finite, results within ±32,767 |
| Diagnostics kept | 1,000 per compile (fea-rs's `max_error_messages`) |
| fea-rs thread | 64 MB stack on native targets |
| Shaping | the existing text limits (`MAX_ITEMS`, `MAX_PREVIEW_ITEMS`); harfrust's own `max_len` and `max_ops`; Text Preview shapes the lines in view and 2 screens around them; a shaping error leaves the line laid out by code point with a message |
| Snippet files | 256 files, 1 MB each, 10,000 snippets |
| Imported `.fea` file | 16 MB, then the limits above |
| Reconstruction | lookups and subtables as the table format allows; output text 16 MB; nested lookup references followed 64 deep |
| Automatic generation | glyph names already capped by `MAX_GLYPHS`; generated code per entry 4 MB |
