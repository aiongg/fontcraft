# M6 plan: components and anchors

_Planning pass of 2026-10-11. Status: **waiting for the owner** (§ 7)._

M6 makes components and anchors editable. It adds the component commands (add, create from the
glyph database, move, swap, lock, decompose, Component from Selection), automatic alignment with
its derived metrics and the `=+N` and `=-N` offsets, anchors (add, rename, move, Set Anchors and
Reset Anchors) and their propagation into composites, recipes in Add Glyphs, smart glyphs and
smart components, corner components, the Pixel tool, the Edit View display and Info boxes for all
of them, the Font View pieces (the Components column, batch actions, smart-filter rules) and the
component export options. § 7 asks the owner whether M6 also writes mark attachment into exported
fonts and whether it builds caps, segments and brushes.

## 3. Answers and decisions

### Design decisions (new questions of this pass)

| Question | Answer for M6 |
|---|---|
| Where the component logic lives | A new crate `components` (L2: `model`, `geom`, `glyphdata`), as `docs/architecture.md` plans it: the reverse component index and dependency order, anchor propagation, automatic alignment and derived metrics, composition from the glyph database and recipes, the default-anchor table, decomposition helpers. Pure functions; no I/O |
| Aligned positions: stored or computed | Stored, as the reference's files store them. After every font-changing command the engine re-aligns the composites that depend on what changed, in dependency order, inside the same undo step; positions and widths are written to the layers. Opening a `.glyphs` or native file does not re-align, so files and round trips are unchanged until something is edited. Compile reads stored values and needs no alignment step |
| When a layer is aligned | A component is aligned when the font option is off and its `alignment` is 1, or 0 on a layer of components only; 3 aligns it horizontally; −1 never. The single Number-category component behaves as 3 (guess) |
| Opening imported files | UFO, designspace and compiled fonts are aligned when the engine opens them unless the user setting Disable Automatic Alignment for Imported Files is on (handbook). The io round trips do not go through this step |
| Anchor propagation | fontc's algorithm, ported, for the editor (alignment, mark targets) and the compiler. It is the same in both oracles and gives top and bottom as the handbook says; it also propagates the other names, which goes beyond what the handbook states (guess on `components.topBottomAnchorsPropagate`). Propagated anchors are computed, never stored, and cached per glyph `Arc` and revision |
| Smart and corner components in outlines | The model's outline resolution draws smart components (`model/smart.rs`) and applies corner components (fontc's `corner_components.rs`, ported to `model/corner.rs` with credit), so Edit View, measurements, metrics and export see one outline |
| Composition data (D6) | Unicode canonical decomposition, added to the glyph database at generation, mapped to glyph names (U+0301 → acutecomb), with the preferred-mark rules and our own tables for what Unicode does not decompose (i, j, ligatures by name parts) and for default anchors; measured against the corpus (§ 5). § 7, question 3 |
| Component commands and selection | Commands address components by shape index on a layer (`components: [indices]`), as M3 addresses paths. Aligned components refuse moves and position edits with a message, except the vertical part for alignment 3 |
| Locks | `component.lock` and `path.lockPath` set the same `locked` flag and share one implementation |
| Limits | § Limits |
| Undo | Every font-changing command is one undo step with its re-alignment; a refused command leaves the font pointer-equal |

### Limits (never crash)

| What | Limit |
|---|---|
| Component depth, cycles | the existing `MAX_COMPONENT_DEPTH` (32); a cycle is a placeholder in the editor and an error at export |
| Components on one layer | 65,535 (the compiler's existing limit) |
| Re-alignment after one edit | each dependent glyph at most once per master; work bounded by the reverse index |
| Recipe | 4,096 bytes, 64 parts |
| Anchors on one layer; name length | 4,096; `MAX_NAME_LEN` |
| Smart properties; pole layers | the existing `MAX_PART_PROPERTIES` (64) and `MAX_SMART_POLE_LAYERS` (64); values finite and within ±`MAX_COORDINATE` |
| Corner scale | finite, at most 100 in absolute value; corners per layer within `MAX_LAYER_HINTS` |
| Pixels in one `pixel.setPixels` | 65,536 cells |
| Create Composite on many glyphs | `MAX_GLYPHS` |
