# M5 plan: spacing, kerning and text mode

_Planning pass of 2026-10-10. Status: **planned**. § 7 lists the owner's questions._

M5 turns Edit View into a place to type and space text. It adds text mode (a tab holds editable
text with a cursor, placeholders, line breaks and a writing direction), metrics keys and the
commands that set sidebearings and widths, kerning pairs and groups with exceptions and locks, the
Info box's spacing and kerning fields, the Kerning window with its maintenance actions, the Font
View inspector's metric and group fields, Transform Metrics, the Preview Area and Preview Panel,
the Text Preview window, sample strings, the measurement line, metrics import and export (AFM and
our kerning-text format), and kerning recovered from compiled fonts.

## 3. Answers and decisions

### Design decisions (new questions of this pass)

| Question | Answer for M5 |
|---|---|
| Where the spacing logic lives | A new crate `spacing` (L2: `model`, `geom`), as `docs/architecture.md` plans it: the metrics-key parser and evaluator, sidebearings measured from resolved outlines (bounding box, and at a height), the out-of-sync scan, linked-master resolution, kerning lookup with its step, lock derivation, group-name checks, Clean Up, Compress, the pair list's filter and sort, and the kerning-text and AFM formats. Pure functions; no I/O |
| Where text layout lives | A new crate `textlayout` (L2: `model`, `spacing`): a text is a list of items (glyph, placeholder, line break); characters map to glyphs by Unicode value and `/name` escapes; a layout places each item with advances, kerning by mode, the writing direction (right-to-left reverses the visual order per line; top to bottom uses vertical widths and origins) and wrapping at the line width. Edit View, both previews, Text Preview, `ui.render` and hit testing all use it |
| Where the tab text lives | In `UiState`: each tab holds its text, the cursor, the selection range, the writing direction and the kerning mode. The text commands are shell commands (§ 2, Kinds). The current glyph is the glyph after the cursor; M3 and M4 code that reads the edited glyph reads it through one accessor |
| Display strings | Opening a document opens one tab per stored string; saving writes the open tabs. A text change is not an undo step and does not mark the document modified (§ 7, question 4) |
| Kerning sides in commands | A side is a glyph name or `@group`. For left-to-right text `@X` on the left means the right group X; on the right, the left group X. For right-to-left text the sides are in logical order and name the group that faces the pair. The engine converts to the stored spelling (`@MMK_L_`, `@MMK_R_`, top and bottom) and back. `direction` defaults to `ltr`, `master` to the first master |
| Locks | Derived, never stored. For the pair at the cursor, a side is open when the pair that applies names that glyph itself while the glyph has a group on that side. `kerning.addException` stores the pair the open lock names at the value that applies, so nothing moves; `kerning.removeException` deletes it in that master. A kerning shortcut changes the value that applies by the step and writes it to the pair the locks name, creating it when needed |
| Out-of-sync state | Computed, not stored, and cached per document revision and glyph `Arc`, as M4's `PropsCache` is, so the Font View badge, the smart-filter rule and the Info box read one result. A change to a glyph recomputes the glyphs whose keys reference it, found through a reverse index |
| Evaluation limits | A key is at most 256 bytes; a reference chain at most 32 steps; a cycle is an error; a width result must lie in 0 to 65,535 and a sidebearing in −32,768 to 32,767. The measured sidebearing reads the resolved outline within the model's existing component-depth and segment limits |
| Linked masters | `spacing::metrics_source(font, master)` gives the master whose widths and kerning a master shows, following the two parameters as fontc does (First Master wins; With Master takes an id, then a name). Edit View shows the linked values; spacing and kerning commands refuse to edit a linked master and name the master it follows (guess). The compiler takes widths and vertical metrics from it for master layers |
| Kerning clipboard and the metrics file | Our kerning-text format (`30-formats.toml`): `left<TAB>right<TAB>value` lines with `@` group sides, group lines and optional metrics lines. The Kerning window copies it as plain text; File › Export › Metrics writes it or AFM |
| AFM | Written for one master with group pairs expanded and exceptions applied; read with group pairs absent. fontTools `afmLib` (MIT) is the oracle in both directions |
| Kerning from compiled fonts | `decompile` reads GPOS pair positioning (format 1 pairs and format 2 classes, extension lookups included) from the `kern` feature's lookups, applies the lookup and subtable order to get the value of every covered pair, and stores class pairs as group pairs (a group named after its first glyph in glyph order) and the rest as glyph pairs, so `kerning.getPair` gives the compiled value for every pair. Counts are capped (§ Limits) |
| Text Preview before M8 | The same layout as Edit View text, with the document's kerning and no other feature; characters the font lacks are drawn in the interface font (§ 7, question 6) |
| Kerning mode default, colours | A new tab starts in kerning mode. The kerned-gap colours are the four `appearance.color.kerning…` settings (negative and positive, light and dark) in the user settings store of M4, with the theme's defaults |
| Sample strings | The `sampleStrings.groups` setting in the user settings store, with a built-in default of our own writing; `edit.selectSampleText` replaces the tab text |
| Edit View line spacing | The `EditView Line Height` parameter when the master has it; else the master's ascender minus its descender, plus 10 % of the em. Lines wrap at the `text.lineWidth` setting, 10,000 units by default |
| Undo | Every font-changing command is one undo step, including a Compress run with `untilStable`, a paste of many pairs and an import. A refused command leaves the font pointer-equal |

### Limits (never crash)

| What | Limit |
|---|---|
| Metrics key length; reference chain depth | 256 bytes; 32 steps |
| Items in an Edit View tab | 10,000 (the existing `MAX_TAB_GLYPHS`) |
| Characters in Text Preview | 1,000,000 |
| Pairs pasted or imported in one command | 500,000 |
| Kerning-text and AFM files | 16 MB, lines of at most 4,096 bytes |

| Glyph search results | 1,000 |

`spacing.evaluateMetricsKey` and `spacing.listOutOfSyncMetrics` (the functions), the Link Metrics
parameters (resolution).

1. `keys.rs`: parse a field's text into `Key { scope: Glyph | Local, body, at }` with
   `body = Name { name, mirrored, op } | Constant | SelfMirror | Signed`; the name is the longest
   leading part that names a glyph; errors carry the byte position. Display form (`==` for a
   local key) and stored form (the layer key without `==`).
2. `measure.rs`: LSB, RSB, TSB, BSB of a layer from its resolved outline's bounds; at a height
   `y` from the first and last crossings of the horizontal line (`measure.sidebearingsAtHeight`'s
   function); empty layers have no sidebearing.
3. Evaluation: one field of one layer, with the referenced glyph's layer chosen as § 3 says,
   rounding halves up, the depth and cycle limits, and the result range.
4. `sync.rs`: the out-of-sync and unlinked scan over a font, with a reverse index (glyph → keys
   that read it); the dependency order for Update Metrics.
5. `link.rs`: `metrics_source(font, master)`.

Tests: every form of the note's table on a synthetic font, both scopes, `|` with an operator,
`@` with and without a crossing, hyphenated names with and without a shorter glyph, a cycle, a
chain of 33, division by zero, a 1 MB key, an unknown glyph; the scan's result unchanged after an
unrelated edit and changed after an edit to a referenced glyph.

Done when: the tests pass, the crate builds for wasm, and the corpus parse check of § 5 is met.
