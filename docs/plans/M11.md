# M11 plan: colour fonts and images

_Planning pass of 2026-10-11. Status: **accepted**: the orchestrator answered § 7 on the owner's behalf; the answers are in § 7 and in the rows._

M11 makes colour fonts and placed images work. It adds colour palettes and their editor, the
four kinds of colour layer (palette, full colour, iColor, svg) with their commands and Layers
palette entries, path attributes (fill, stroke, gradients) and the Attributes inspector, colour
drawing in Edit View, Font View and the previews, and the export of CPAL, COLR version 0 and 1,
sbix and the SVG table, with the instance switches that choose among them. It also adds placed
images: Add Image, the image commands, drawing and manipulating images in Edit View, and images
in Font View cells, which M4 left for this milestone. CBDT and CBLC, which the reference does not
write, are an option of ours, built last (§ 7, question 2). Variable COLR and colour layers in interpolated
instances wait for M9's variation model (§ 6).

## 3. Answers and decisions

### Design decisions (new questions of this pass)

| Question | Answer for M11 |
|---|---|
| Where the colour logic lives | A new crate `color` (L2: `model`, `geom`): palettes as typed data, colour layer kinds and their paint order, the paint graph built from the layers, the resolution of the instance switches into one export plan, strike selection, the SVG document writer and the asset-store trait. Pure functions, no I/O. Edit View, Font View, Text Preview, the SVG writer and the COLR writer all read the same paint graph, so what the canvas shows is what export writes |
| Image decoding | A new standalone crate `imagery` over the `image` crate with only its PNG, JPEG and TIFF decoders, which are already in `Cargo.lock` through the UI stack. It sniffs format and size from the header before decoding anything, and decodes within the limits below. PDF and PSD are kept as references and drawn as an unsupported-image marker (§ 7, question 3) |
| Where image bytes come from | Through `color::AssetStore`, which maps a stored path to bytes. The engine's store reads files relative to the document's folder and caches them by path and modification time; the web build's store holds uploaded files in memory; the compiler receives the store in its options. The compiler and the UI never open files themselves, which keeps both building for wasm and makes export reproducible in tests |
| Images on an unsaved document | The absolute path is stored until the first save, which rewrites it relative to the new file (guess on `image.storedAsRelativePath`) |
| Paint attributes in the model | The model stores colour layers already (`LayerAttrs`). M11.1 adds typed paint attributes to `ShapeAttrs` (`model/src/paint.rs`): colours as RGBA or a palette reference with alpha (the version 4 form), linear, radial and conic gradients with stops and extend mode, shadows. Stroke position is stored in the version 4 convention and converted when a version 3 file is read or written |
| Which layers make a colour glyph | Per glyph and master: the special layers associated with that master, in their order in the file, the first painted first (at the bottom), as both oracles write it. Palette and full-colour layers feed COLR and the vector SVG documents; iColor layers feed sbix (and CBDT); an svg layer feeds the SVG table |
| Palettes per master | A master's own `Color Palettes` wins over the font's for that master's layers and for exports from it, as both oracles read it (`color.palette.perMaster`) |
| COLR version | Version 0 when every colour glyph is a stack of solid layers (palette layers, or full-colour layers with only solid fills), version 1 as soon as one glyph needs a gradient. This is fontc's rule; fontmake writes version 1 for every full-colour glyph. Recorded in `docs/spec/40-compile.md` § 4a by M11.7 (guess on `color.export.colrVersionChoice`) |
| Layer glyphs | `<base>.color<i>`, numbered by position among the base glyph's colour layers after merging consecutive shapes with equal attributes, named from the base glyph's production name, appended after the source glyphs in numeric order, never shared between glyphs: fontc's naming and order, and both oracles' merging and sharing. Colours that are not palette references are added once to every palette, with their alpha in CPAL only (fontmake adds them per use and applies alpha twice) |
| Strokes in COLR | COLR has no stroke paint, so a stroke is expanded to an outline with the stroke code `path.setStroke` already uses, respecting width and position, and becomes its own layer above the fill (guess on `color.export.strokeInColr`) |
| SVG documents | One uncompressed document per glyph; the glyph's group has the id `glyph<ID>` and a transform that flips y at the baseline, combined with the placed image's transform for svg layers; palette colours are baked in from `Color Palette for SVG`. This is nanoemoji's `untouchedsvg` layout; no oracle writes an SVG table from a Glyphs source |
| sbix data | One strike per distinct iColor size at 72 pixels per inch; PNG and JPEG data stored byte for byte with the tags `png ` and `jpg `; TIFF converted to PNG (renderers do not draw `tiff` reliably); origin offsets from the image's position on the iColor layer, in pixels; header flag bit 0 set, the draw-outlines bit 1 clear, which is what write-fonts can write (guess on `color.sbix.bitmapFormats`) |
| Width of colour layers | Colour layers always carry their master layer's width: a width change on a master layer writes the same width to its colour layers in the same undo step (`color.layers.widthFollowsMaster`) |
| Commands and targets | Commands address layers by glyph name and layer id and paths by index, as M3 and M6 do. Converting a master layer is refused; converting a colour layer to another kind replaces its kind |
| The palette editor | Keeps a staged copy; OK runs the edits as one `command.batch`, so the editor is one undo step and each edit is still the command an agent would run |
| Instance switches | Read per instance by `color::export::plan`, the single source for every table builder and for `color.describeExport`. Defaults, from the handbook and the appendix: CPAL and COLR whenever palette or full-colour layers exist, sbix whenever iColor layers exist, the SVG table whenever svg layers exist or a conversion asks for it; each `Export … Table` parameter set off removes its table |
| Colour export of interpolated instances | Refused with a message naming the instance until M11.19 (§ 6) |

### Limits (never crash)

| What | Limit |
|---|---|
| Image file read for display or export | 64 MiB (`imagery::MAX_FILE_BYTES`) |
| Decoded image | 16,384 pixels on a side and 2^26 pixels (`imagery::MAX_SIDE`, `MAX_PIXELS`); the header is checked before decoding |
| TIFF | the first page only; at most 1,024 IFD entries |
| Image cache | 512 MiB of decoded textures in the UI, least recently used evicted; the engine's byte cache 256 MiB |
| Images in one Add Image call | 10,000 files |
| Palettes; colours per palette | 256 palettes; 65,534 rows (index 65,535 is the text colour) |
| Colour layers per glyph and master | 1,024 |
| Gradient stops | 256 per gradient; offsets finite and clamped to 0..1 when written |
| iColor size | 1 to 4,096 pixels per em |
| Paint graph | depth 64; 65,535 layer glyphs in total, within `MAX_GLYPHS` with the source glyphs |
| SVG file read for an svg layer | 16 MiB, parsed by usvg without text or system fonts, nesting at most 256 deep, no external references |
| SVG document written | 16 MiB per glyph; the table 512 MiB |
| sbix and CBDT | strikes at most 64; each image at most `MAX_FILE_BYTES` |
| Coordinates (image transforms, gradient points) | finite and within ±`MAX_COORDINATE`; scale not 0 |

### Guesses

Every choice of ours where no source says what the reference does is in a row's `guesses`: 47
entries on 45 M11 rows, all new. With them the inventory goes from 678 guesses on 435 rows to 725
on 480. `docs/parity.md` and `docs/guesses.md` are regenerated by M11.0. Each guess names what
would settle it, and each has a check in § 8. The ones with the most effect:

- Export without an oracle: the instance switches, the SVG document layout, sbix data and
  placement, mixed kinds, layered conversions: `color.export.colorPaletteForCpal`,
  `color.export.exportSvgTable`, `color.export.fullColorToSvg`, `color.svg.imageTransform`,
  `color.sbix.bitmapFormats`, `color.export.sbixAutomatic`, `color.fourKinds`,
  `color.layered.toColr`, `color.layered.toSvg`.

  COLR: `color.export.colrVersionChoice`, `color.export.fullColorToColrV1`,
  `color.export.strokeInColr`, `color.export.variableColr`.
- Editing defaults: palette rows and palettes, layer conversion, the iColor size and placement,
  gradient and stroke defaults: `colorPalette.addColor`, `colorPalette.removeColor`,
  `colorPalette.removePalette`, `layer.convertToColorPalette`, `layer.convertToIColor`,
  `layer.setIColorImage`, `attributes.addGradient`, `color.fullColor.defaultGrayFill`,
  `attributes.setStrokeAlignment`.
- Images: one image per layer, placement and resolution, crop space, unsaved documents,
  formats, batch matching: `glyph.addImage`, `image.defaultPlacement`, `image.setCrop`,

### M11.1 Interface skeleton (builder)

Everything later packages compile against, with placeholder bodies that return a "not built yet"

1. **`crates/color`** (L2: `model`, `geom`). Pure functions, no I/O.
   - `palette.rs`: `Rgba` (four `u8`), `Palettes { rows: usize, palettes: Vec<Vec<Rgba>> }` with
     the invariant that every palette has `rows` entries; `read(&Font, master: Option<&str>) ->
     Result<Palettes, ColorError>` (a master's own `Color Palettes` wins, § 3);

     `remove_palette`, each returning a new `Palettes` or an error.

     `kind(&Layer) -> Option<ColorLayerKind>`, `color_layers(&Glyph, master_id) -> Vec<(&Layer,
     ColorLayerKind)>` in paint order (bottom first), `label(&ColorLayerKind) -> String`

     Bitmap, Svg, Mixed }` for the query tokens.

     extend }`, `ColorRef { Palette { index, alpha }, Foreground { alpha }, Rgba([f64; 4]) }`,
     `ShapeRef { layer, path, stroke: Option<StrokeSpec> }`; `glyph_paint(&Font, &Glyph,
     master_id, &Palettes) -> Result<Option<Paint>, ColorError>`. Outlines are not drawn here:
     callers draw a `ShapeRef` with their own outline code, so `color` needs no `pathops`.
   - `export.rs`: `Switches` (the eight instance parameters, § 9 of the notes), `read_switches(
     &Font, instance) -> Switches`, `ExportPlan { cpal: Option<CpalPlan>, colr: Option<ColrPlan>,
     sbix: Option<SbixPlan>, svg: Option<SvgPlan>, cbdt: Option<CbdtPlan>, problems:
     Vec<Problem> }`, `plan(&Font, instance) -> ExportPlan`. `color.describeExport` and every
     table builder read this one plan.

     rule), `aspect_problems(...)`.

     palette: &[Rgba]) -> Result<String, ColorError>`, `bitmap_document(png: &[u8], placement,
     gid) -> String`, `table(docs: &[(u16, u16, Vec<u8>)]) -> Result<Vec<u8>, ColorError>`.
   - `assets.rs`: `trait AssetStore { fn read(&self, path: &str) -> Result<Arc<[u8]>,
     AssetError>; fn exists(&self, path: &str) -> bool; }`, `MemoryAssets` (tests and the web

3. **`crates/model/src/paint.rs`**: `Color { Rgba([f64; 4]), Palette { index: u16, alpha: f64 }

### Independent of M9

Everything except M11.19 is independent of M9. Static exports of a master, of an instance that
sits on a master, and of a single-master font need no interpolation, and that is what the
oracles' colour test sources build. Two things wait for M9: colour layers in an instance
between masters (interpolated like the masters' own layers), and variable COLR in a variable
font. Until M11.19, an instance between masters with colour layers is refused for colour
export with a message naming the instance, and a variable build writes no COLR, with a warning;
no stub removes this dependency, because the interpolation itself is the missing part.

## 8. To check in the reference app

Each check names the row it settles. The test fonts are built in code (`crates/testkit`) and
saved as `.glyphs` for the trial:

- **Palette font**: 1,000 units per em, one master; `Color Palettes` with two palettes of three
  colours (red, green, blue; cyan, magenta, yellow); glyph `A` with three palette layers (index
  0, `*`, 1) whose outlines differ; glyph `B` with one palette layer whose outline equals one of
  `A`'s; a fallback outline on each master layer.
- **Full-colour font**: glyph `C` with a Color layer holding three paths: a solid fill, a linear
  gradient, and an open path with a 20-unit stroke; glyph `D` with a radial gradient.
- **sbix font**: glyph `E` whose master layer has two zero-size corner paths at (50, −100) and
  (550, 700); PNG files `E 64.png` (64 × 64) and `E 128.png` (128 × 128), a JPEG and a TIFF of
  the same picture, and a non-square PNG.
- **SVG font**: glyph `F` with an svg layer referencing `Images/F.svg` (a 100 × 100 viewBox with
  a gradient and an embedded PNG).
- **Layered font**: a Color axis, three masters at 1, 2, 3 with Master Color red, green, blue
