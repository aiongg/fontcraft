# M12 plan: command-line tool suite and quality checks

_Planning pass of 2026-10-11. Status: **accepted**: the orchestrator answered § 7 on the owner's behalf; the answers are in § 7 and in the rows._

M12 turns `fontcraft-cli` into a full font tool suite and completes the font audit. On the
command-line side it adds the table actions, dumps in the fontTools XML dialect and in readable
views, glyph renaming and reordering, conversion between outline flavours and containers,
subsetting, instancing, merging, transforming, optimising, collections and WOFF, outline repairs
on whole files, a table-by-table diff, layout tools, variation utilities, proof sheets and timing.
Each subcommand is a thin shell over one engine command and is compared with a reference tool
(AFDKO, fontTools, fontc, fontmake). On the audit side it adds 240 checks to the 34 outline checks
of M3: checks on compiled fonts (binary scope), on families, and the source checks that need
components, kerning or masters, with profiles, ignore lists, reports, fixes on compiled fonts and
in sources, and the Font Audit panel. Following the owner's request during this pass, M12 also
takes in our own versions of the reference vendor's free companion tools that belong to the engine
track: a table viewer with a font comparison, and a source comparison with merging (§ 1).

The plan is written for wide fan-out: three interface packages first (M12.1a, b and c, in
parallel), then 63 packages that each own their own files.

## 3. Answers and decisions

### Design decisions (new questions of this pass)

| Question | Answer for M12 |
|---|---|
| Where the binary tools live | A new crate `tables` (L3), as `docs/architecture.md` plans it: sfnt reading and writing with table pass-through, table actions and `tables.show`, collections, the TTX writer and reader, text views, layout normaliser and feature-code writer, VOLT and FontDame readers, glyph rename and reorder, metrics, subset, instance, merge, transform, optimize, dehint, outline rewriting, conversion, diff, variation utilities, GOADB and FontMenuNameDB. It depends on `model`, `geom`, `pathops`, `cff`, `container`, `compile` (glyph encoders) and `decompile` (glyph decoders), which needs two same-layer entries in `xtask/src/layers.rs` (`compile` → `tables`, `decompile` → `tables`). One module per tool, so packages own disjoint files |
| How binary edits are made | Tables a tool does not touch are copied byte for byte (`cli.global.sourceOrBinary`). Touched tables are read with read-fonts, turned into write-fonts' owned types, changed and written. Unknown tables pass through. The directory, checksums and `head.checkSumAdjustment` are always recomputed; the table order is the specification's recommended order unless the tool keeps the input order |
| Where proofs live | A new crate `proof` (L3): page layout, SVG and HTML writers, the PDF writer on `pdf-writer` (§ 7 question 3); drawing through `render` and skrifa |
| How a subcommand reaches the engine | A subcommand file parses its options into one engine command's parameters and prints its result (`cli.global.commandDispatch`). File-level commands take paths (`{font: path, output?: path, …}`), run under `guard`, never change their input, write atomically, and refuse on wasm with a message. For sources, a whole-file command opens the document, runs the document command on each glyph (decision D2: one implementation per action) and saves |
| The option parser | Our own, in `apps/fontcraft-cli/src/args.rs`: each subcommand declares its options as data (name, value kind, list or switch, default, help); the parser gives `--x`/`--no-x`, `--opt=a,b`, `--opt=+c,-a`, `@FILE`, `--options FILE` with left-to-right precedence, unambiguous prefixes, and `--help` and `completion` generated from the same tables. No new dependency |
| Exit status (20-cli question 20) | 0 nothing to report, 1 something found, 2 usage, 3 unreadable input, 4 operation failed, 5 some inputs of a batch failed, 130 interrupted, for every subcommand including `check` (`audit.exitStatus` already says 3) |
| Check scopes in the registry | `CheckSpec` gains a scope (layer, glyph, source, binary, family), its group (the 16 groups replace the four outline families), preconditions, and a severity per message code. Its runner is one of five function types, one per scope. The registry is split into one file per group (`registry/<group>.rs`) so check packages never edit the same file |
| How L2 checks reach L3 services | The audit stays L2 and gains read-fonts and skrifa. What a check cannot compute at L2 (an in-memory compile, a TTX round trip, shaping, the master-compatibility report) comes through an `AuditServices` trait that the engine implements. A missing service makes the check skip with a reason |
| Master compatibility | The structural comparison (missing glyph, path count, node count, node type, component and anchor mismatch) is M9's routine behind `interpolation.checkCompatibility`; the audit receives its report through `AuditServices` in a type `audit` defines, so the two can never disagree (`21-qa.md` § 3). Until M9 lands, the engine fills the report with a plain structural comparison of its own in `cmd/audit_services.rs`, replaced by M9's routine afterwards. The heuristic tests (contour order, start point, kink, under- and overweight) are a port of `varLib.interpolatable` (MIT) inside `audit` |
| Fixes without a command (`21-qa.md` question 2) | Each becomes an engine command in the inventory, added by M12.0: outline and glyph fixes as `own = true` rows in `21-qa-checks.toml` (for example deleting reported contours, removing duplicate components, snapping handles, zeroing mark widths); compiled-font fixes as `tables.*` options (`patchTable`, `dropTables`, `cleanNameRecords`, `rebuildCmap`, `recompileCff`); Font Info fixes as calls to M7's commands |
| Audit settings storage | Profiles of the user in the application settings; project profiles, the default profile, threshold overrides, project values and the ignore list in the source's font user data under a FontCraft key, which round-trips through `.glyphs`, UFO and the native format. No new model field |
| Data the checks need (`21-qa.md` question 7) | Registered script, language, feature and baseline tags from the OpenType registry pages (facts, typed as data); Unicode ranges and code pages ported from fontTools' `OS/2` table code (MIT, credited); expected contour counts and the case-mapping exceptions ported from FontBakery's data files (Apache-2.0, credited); production names from `glyphdata`. In `audit/src/data/`, each file with its source in the header |
| Subsetting | A port of pyftsubset (MIT, credited), table by table, with its option names; HarfBuzz's subsetter (through uharfbuzz) as a second oracle |
| Instancing | A port of `varLib.instancer` (MIT, credited): full instances, partial pinning, and axis ranges with its region solver |
| Compatibility shims (20-cli question 16) | None in M12: the binary does not react to being called `makeotf` or `tx`. The option-mapping tables of `20-cli.md` make them possible later |
| Type 1 and `.dfont` (20-cli questions 11, 12) | Type 1 reading in M12; no Type 1 writing (§ 7 question 5). `.dfont` stays not carried over |

### Limits (never crash)

| What | Limit |
|---|---|
| Input font, collection, WOFF or WOFF2 | `container::MAX_SFNT` (256 MiB) after decompression; WOFF2 declared sizes checked against it before allocating |
| Tables in one font | `container::MAX_TABLES` (1,024) |
| Fonts in one collection; fonts merged; fonts in one family | 256; 64; 256 |
| TTX input | 256 MiB of text, element depth 64, 50,000,000 elements, hex data within `MAX_SFNT` |
| TTX and JSON output | 1 GiB of text, the JSON element tree counted with it; 8,388,608 `cmap` mappings over all subtable records |
| Table copies | one font's tables `MAX_SFNT` in all; an unpacked collection 4 × `MAX_SFNT` in all, counted from the directories before copying |
| Glyphs in a list, map or GOADB | `model::MAX_GLYPHS` (65,535); GOADB and map lines 1,024 bytes |
| Subset text file, code point list | 16 MiB; 1,114,112 code points |
| Layout closure and contextual nesting | each lookup visited at most once per glyph set change, nesting depth 64, closure rounds bounded by the glyph count |
| CFF charstrings | subroutine nesting 10 (the specification's limit), argument stack 48 (CFF) and 513 (CFF2), charstring length 65,535 bytes |
| Instancing | axes within `model::MAX_AXIS_VALUES` (64); locations finite; tuple variations per glyph 65,535 |
| Transform | matrix values finite; results outside ±32,767 in `glyf` refuse the run; units per em 16 to 16,384 |
| Response files, options files | 1 MiB each, `@FILE` nesting depth 8, cycle detection |
| Batch | 100,000 inputs; `--jobs` at most 256 |
| Diff output | 1,000 differing records per table and 64 KiB of hex per table unless `--all` |
| Proof | 10,000 pages; 65,535 glyphs per sheet set |
| VOLT, FontDame, feature code input | 64 MiB each |
| Audit | findings per check per font `MAX_FINDINGS_PER_CHECK`; profile includes depth 8 with cycle detection; ignore list 100,000 entries; external tools (sanitiser, validator) 60 s each, opt-in |
| Source diff | changes listed 1,000,000; glyph comparison under the existing outline limits |
| Glyph data files (M14 rows) | the `glyphdata` custom-file limits |

## 4. Packages

"B" packages run in the main checkout, one at a time. "W" packages run in parallel worktrees
without builds and run one compile check before committing. "W+B" packages are written in a
worktree against small expected outputs that the package generates with the oracle into its test
data (text, never compiled fonts); a builder then runs the corpus measure once after integration
and sends the differences back. Every package registers its commands in the module M12.1a already
created for it, so no package edits `cmd/mod.rs`, `xtask/src/layers.rs` or the root `Cargo.toml`,
and edits only its own rows' `notes` and `guesses` when behaviour turns out different.

### M12.66 Outline repairs on CFF (writer, wave 3)

`outlines` refuses CFF fonts (`crates/tables/src/outlines.rs`), although checkoutlinesufo and
`tx +V` repair OTF files and `convert --remove-overlaps` already merges CFF overlaps. This package
runs the four repairs on `CFF ` and static `CFF2` and keeps every other table byte for byte. The
overlap merge reuses `convert/overlaps.rs`; merged glyphs lose their hints, as with `tx +V`, and
unchanged glyphs keep theirs. A subroutinised input comes out subroutinised. `-j` runs through
`io::batch`.
Rows: `outlines` and its four repair actions; `outlines.removeOverlaps`, `.correctDirection`,
`.addExtremes`, `.roundCoordinates`.
Needs: M12.67.
Files: `tables/src/outlines.rs`, new `tables/src/outlines_cff.rs`, `cmd/outlines_file.rs`,
`sub/outlines.rs`.
Tests: each repair on a CFF font built in code; untouched tables identical; hints kept on
unchanged glyphs.
