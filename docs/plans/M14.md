# M14 plan: 1.0 polish (depth packages)

_Status: depth packages only. The full milestone plan is written when M14 starts._

## 1. Scope

M14 is the 1.0 polish milestone: the settings window, the shortcuts editor, languages,
accessibility, packaging and the web build. It adopts the suite's `craft-ui` (docking, tabs, icon
buttons, widget-state theme; decision 0008). This file holds only the packages of the second
planning pass for the Window, tabs, settings and shortcuts area. Updates and crash reports are
left out: both need a hosted service.

## 2. Depth packages

These packages come from the second planning pass, which graded the area by behaviour against the
spec and listed what closes the gaps. The waves, the builder queue and the open decisions are in
[`depth.md`](depth.md). Writers write tests but run none; builders run the narrow tests and the
measure named.

Grade: Window, tabs, settings, shortcuts 24% now → 39% after these packages (46% with the
craft-keymap packages M14.7 and M14.8).

### M14.1 Settings window and the User Settings section (writer, wave 1)

`app.settings {section?}` (Cmd+Comma) opens a window with the seven sections in handbook order;
sections not built yet are listed greyed with the reason. A `Section` hook lets other packages fill
their section: Sample Strings (M5.29) and Sharing. Every control runs `settings.set`, and each new
id gets a `SettingDef`. The Add-ons section hosts the Extension Manager's Indexes tab.

Rows: `app.settings`, `window.settings`, `settings.userSettings`, `user.disableLocalization`,
`user.sendCrashReports`, `user.crashReportName`, `user.crashReportEmail`,
`user.localizationNeedsRestart`, `settings.menuItemNameOnOlderSystem`, `settings.addons`;
`user.keepGlyphNamesFromImportedFiles` and `user.useVersions` (ids and controls only).
`settings.resetWarnings` has no source and is dropped.
Needs: none.
Files: new `shell/settings_window/{mod,user,addons}.rs`, `shell/mod.rs`, `engine/src/settings.rs`
(`SETTINGS`), `shell/extensions/manager.rs` (Indexes tab body as a shared function),
`spec/inventory/16-settings.toml`.
Tests: open on a section; a control writes its setting; a refused value changes nothing; a frame
test per section.
Measure: every handbook control reachable by `settings.set` and the control channel.
Guesses: Settings… sits in Edit off macOS; Disable Localization, Use Versions and the crash-report
fields are stored without effect.
Observe: section order; the default of every checkbox.

### M14.2 Appearance section, light and dark (writer, wave 3)

The window follows the system appearance unless a setting overrides it. The two Always use Light
Mode switches apply to Font View and Edit View content. Standard resets both colour sets in one
`settings.set` batch. The colour and handle-size setting ids, `Kind::Color` and the tokens belong
to M3.23; this package builds the section on them and picks the colour set of the appearance in
use.

Rows: `settings.appearance`, `appearance.alwaysLightModeFontView`,
`appearance.alwaysLightModeEditView`, `appearance.colorsPerSystemAppearance`,
`settings.resetColors`, `view.fillColorFromSettings`.
Needs: M14.1, M3.23.
Files: new `shell/settings_window/appearance.rs`, `theme.rs`, `app.rs` (where tokens are chosen),
`16-settings.toml`. Keep the egui `Visuals` setup in one function so M14.9 can replace it.
Tests: a stored corner-node colour reaches the canvas tokens in light and dark; Always use Light
Mode for Edit View gives the light canvas under a dark system; Standard restores the defaults.
Measure: a light and a dark screenshot of Font View and Edit View with a changed colour.
Guesses: Always use Light Mode changes the view's content, not the window chrome.
Observe: the default colours.

### M14.3 Save prompts on close and quit, `app.quit`, the title (builder, wave 1)

Closing the window loses unsaved work today. This package adds `app.quit {discard?}` (Cmd+Q; File ›
Quit off macOS) and adopts the suite's craft-quit. The close box, Cmd+Q or `file.close` on a
modified document opens a prompt per document: Save, Don't Save, Cancel. A failed save or a
cancelled chooser keeps the app open. Headless `app.quit` without `discard` refuses while documents
are modified. The OS title shows the document name with an edited mark. It runs first, because it
is the only gap that loses user work.

Rows: `app.quit` (`memory` → `inferred`), `file.close` (window behaviour), new rows
`window.closePrompt` and `window.titleShowsDocument` (`inferred`).
Needs: none.
Files: `apps/fontcraft/src/main.rs`, `apps/fontcraft/Cargo.toml`, root `Cargo.toml` (craft-quit at
the pin of the other craft crates), new `shell/close_prompt.rs`, `app.rs` (shared with M1.8),
`spec/inventory/00-app-basics.toml`.
Tests: a close request on a modified document shows the prompt and cancels the close; Don't Save
closes; a failing Save keeps the window; `app.quit` refuses headless.
Measure: an end-to-end control-channel run that edits, requests close and answers the prompt.
Observe: one prompt per document or one review list; button order; what Cmd+Q does with several
documents; the title format and edited mark.

### M14.4 Option alternates, Palette button, About (writer, wave 6)

One mechanism covers the Option alternates of every menu. A menu item may name an alternate; while
Alt is held the alternate replaces it with its own label and shortcut, and it is hidden otherwise.
The pairs: the "for All Masters" twins, Delete in All Masters, Force Extremes after Add Extremes,
Set and Reset Anchors for all masters, Expand Outline for all masters, Reopen Last Closed Tab after
Close Tab, Add Selection to Background after Selection to Background, Clear Background after Assign
Background…. `ui.menu.list` reports `alternateOf`. The package also adds a Palette button at the
toolbar's right end (`window.palette`) and `app.about` (version, licences from `NOTICE` and
`ASSETS.md`, graphics backend; Help › About FontCraft off macOS).

Rows: `menus.optionRevealsAlternateItems`, `app.about`, the Palette button in `palette`'s notes,
the Alt forms of `path.addSelectionToBackground`, `path.clearBackground` and `fontView.batch.*`.
Needs: none.
Files: `shell/menus.rs` (`ALTERNATES` table), `shell/menus_dynamic.rs`, `app.rs` (`menu_items`),
`shell/toolbar.rs`, new `shell/about.rs`, inventory rows.
Tests: the menu tree with and without Alt; a frame test of the toolbar button.
Observe: which items Option swaps, their labels, and whether the swapped item keeps the shortcut
with Alt added.

### M14.5 Canvas scroll bars, number expressions (writer, wave 6)

Thin scroll bars along the canvas's right and bottom edges, sized from the text's extent and the
view; dragging one runs `view.scrollTo`. Number fields in panels and dialogs accept `+ - * /` and
parentheses and replace the text with the result on Return. Input is capped at 256 bytes and depth
32; non-finite results are refused.

Rows: `pan.scrolling` (scroll bars), `ui.numericFieldExpressions`.
Needs: none.
Files: new `canvas/scroll_bars.rs` (called from one line in `canvas/mod.rs`),
`panels/widgets.rs`, `dialogs/mod.rs`.
Guesses: the slider part of the expressions row is left out.

### M14.6 Master display parameters (writer, wave 6)

The Edit View canvas takes the active master's background colour for the appearance in use. A
master without an icon shows the glyph named by Master Icon Glyph Name. Master Stroke Color and
its Dark form wait on open decision 1 in `depth.md` (the Select All Layers tool).

Rows: `Master Background Color`, `Master Background Color Dark`, `Master Icon Glyph Name`.
Needs: M14.2.
Files: the canvas background in `canvas/`, `master_icons.rs`, `master_switcher.rs`.

### M14.7 Adopt craft-keymap (builder; waits on upstream craft-keymap PR 164)

The suite's keymap takes over shortcut dispatch. The catalog comes from `command_specs()` and
`UI_COMMANDS`; overrides live in the settings file; menus show `Chord::display`; system chords are
reserved. `shell/keymap.rs` dispatches through the keymap, with `Cmd+Alt+2…9` and `Cmd+1…9` as
parameterised bindings. The headless commands live in `engine/src/cmd/shortcuts.rs`. The package
pins the merge commit, which bumps every craft crate. It waits on open decision 8 in `depth.md`.

Rows: `shortcuts.custom`, `shortcuts.oneRegistry`, `shortcuts.composition`,
`shortcuts.keySymbolDisplay`, `shortcuts.platformMapping`, `spacing.ctrlArrowSystemConflict`,
`settings.listShortcuts`, `settings.removeShortcut`, `settings.resetShortcut`, new row
`settings.setShortcut`.
Needs: upstream PR 164.
Files: `shell/keymap.rs`, M4.18's keys function, `engine/src/cmd/shortcuts.rs`.
Measure: every registry shortcut dispatches as before (a table test over the catalog).

### M14.8 Shortcuts section (builder; waits on upstream craft-keymap PR 186)

The suite's `ShortcutsDialog::ui` is the body of Settings › Shortcuts; `Outcome::Changed` rebuilds
the menu cache. The reference's four scope buttons (All, Customized, Menu, Commands) map to the
dialog's filters; anything missing goes upstream. It brings craft-ui and craft-i18n into `ui-egui`.
It waits on open decision 8 in `depth.md`.

Rows: `settings.shortcuts`, `settings.recordShortcut`, `settings.cancelShortcutRecording`,
`settings.filterShortcuts`, `settings.toggleShortcutSection`, `shortcuts.scopeFilters`,
`shortcuts.sections`, `shortcuts.search`.
Needs: M14.7, upstream PR 186.
Observe: what the Commands scope lists; whether a key without a modifier can be recorded.

Rows: `app.commandPalette`; `app.quickHelp` if room remains.

### X.suite3 craft-settings store and window frame (builder, wave 12)

Settings move to `config.toml` through craft-settings' `SettingsStore`, with a one-time import of
`settings.json`. `FONTCRAFT_SETTINGS_DIR` stays the override (empty keeps settings in memory, as in
the suite). The reserved ids (filters, recent documents) are unchanged. The window's size, position
and maximised state and the Palette's visibility are stored and restored at start. The engine's
JSON values map to one `[settings]` table of strings, numbers, booleans and tables; `null` removes
the key.

Rows: `settings.surviveVersionChange`, the notes of `settings.set` (file name and layout), new row
`window.frameKept` (`inferred`).
Needs: M14.3 (both edit `main.rs`).
Files: `apps/fontcraft/src/user_files.rs`, `main.rs`, `Cargo.toml`; `engine/src/settings.rs` only if
the store needs a section map.
Observe: whether window frames are kept per document or per app.
